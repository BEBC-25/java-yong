# 1. 프로그래밍의 이해

## 1.1 프로그래밍이란?
- 프로그램이란 컴퓨터에 내리는 명령의 집합이고 이를 만드는 과정을 프로그래밍이라고 함
- 컴퓨터의 CPU는 0과 1로 이루어진 기계어만 이해할 수 있는 단순한 연산 장치
- 컴퓨터에게 명령을 내리기 위해 인간이 0과 1로 구성된 기계어를 직접 작성하기는 매우 어렵기 때문에 인간이 이해하기 쉽도록 인간의 언어와 유사한 프로그래밍 언어(고급 언어)를 만들어서 사용
- 대표적인 프로그래밍 언어로 C, Java, Python, Javascript 등이 있음
- 고급 언어로 만들어진 코드를 `소스 코드`라고 함
- 소스 코드는 인간이 이해 가능하지만 컴퓨터가 이해할 수 없으므로 컴퓨터가 이해할 수 있는 `기계어`로 변환해야 하는데 이 과정을 컴파일 또는 인터프린팅이라 함

## 1.2 컴파일러와 인터프리터
- 컴파일: 개발자가 작성한 소스 코드를 컴퓨터가 이해할 수 있는 기계어로 한 번에 번역하는 과정
- 컴파일러: 컴파일을 수행하는 프로그램
- 인터프리팅: 소스 코드를 한 줄씩 읽어가며 기계어로 즉석에서 번역하는 과정
- 인터프리터: 인터프리팅을 수행하고 그 결과를 즉시 실행하는 프로그램

## 1.3 컴파일러 언어 vs. 인터프린터 언어
### 1.3.1 컴파일러(Compiler) 언어
- 코드를 실행하기 전, 전체 소스 코드를 한 번에 기계어로 번환(컴파일)하여 실행 파일을 만드는 방식
- 특징
  + 실행 속도가 매우 빠르지만, 코드를 수정할 때마다 다시 컴파일해야 하므로 개발 속도는 상대적으로 느릴 수 있음
  + CPU 아키텍처마다 사용하는 명령어 집합이 다르기 때문에 그에 맞게 기계어가 생성되어야 하고, 프로그램이 메모리를 할당받거나 화면에 글자를 출력할 때 OS에 요청을 보내는 `시스템 콜`이 OS마다 다름. 결과적으로 컴파일된 결과물은 특정 플랫폼(CPU + OS)에 종속됨
- 대표적인 언어
  + C / C++: 시스템 프로그래밍이나 게임 엔진 개발에 주로 쓰이며 성능이 매우 강력함
  + Rust: 메모리 안전성을 보장하면서도 C++에 준하는 성능을 내어 최근 각광받고 있음
  + Go (Golang): 구글에서 개발했으며, 컴파일 속도가 빠르고 병렬 처리에 강점이 있음

### 1.3.2 인터프리터(Interpreter) 언어
- 코드를 실행할 때 전체를 미리 번역하지 않고, 한 줄씩 읽어가며 즉석에서 기계어로 번역과 실행을 동시에 수행하는 방식
- 특징
  + 실행 파일을 미리 만들지 않으므로 코드를 수정한 후 즉각적인 확인이 가능해 개발 속도가 빠름
  + 코드를 실행할 때마다 매번 번역을 거쳐야 하므로 컴파일러 언어에 비해 실행 속도는 상대적으로 느림
  + 각 운영체제에 맞는 인터프리터만 설치되어 있으면 동일한 코드를 어디서든 실행할 수 있어 플랫폼에 독립적
- 대표적인 언어
  + Python: 문법이 직관적이고 간결하여 기초 교육부터 데이터 분석, 인공지능 분야까지 폭넓게 쓰임
  + JavaScript: 웹 브라우저에서 동작하는 유일한 언어로 시작해, 현재는 프론트엔드와 백엔드를 아우르는 거대한 생태계를 가짐
  + Ruby: 개발자의 생산성을 극대화하는 데 초점을 맞춘 언어로, 웹 프레임워크인 Ruby on Rails를 통해 널리 쓰임

### 1.3.3 하이브리드(Hybrid) 언어
- 소스 코드를 바이트코드(중간어)로 1차 컴파일한 뒤, 실행 시점에 가상 머신(VM)을 통해 기계어로 번역하며 실행하는 혼합 방식
- 특징
  + 컴파일 단계를 통해 실행 전에 문법 오류를 잡을 수 있고, 가상 머신이 실행 환경에 맞게 번역해주므로 운영체제에 독립적
  + 인터프리터의 느린 속도를 보완하기 위해 JIT 컴파일러 등을 활용하여 자주 쓰이는 코드를 기계어로 캐싱
- 대표적인 언어
  + Java: 가상 머신(JVM, Java Virtual Machine) 위에서 동작하며, 엔터프라이즈급 백엔드 서버 개발에 전 세계적으로 가장 많이 쓰이는 언어임
  + C#: 마이크로소프트 환경과 닷넷(.NET) 환경에서 구동되며, 특히 게임 개발 등에서 뛰어난 생산성과 성능을 발휘

### 1.3.4 세 방식의 언어 비교 요약

| 구분 | 컴파일러 언어 | 인터프리터 언어 | 하이브리드 언어 |
| :--- | :--- | :--- | :--- |
| 동작 방식 | 실행 전 전체 소스 코드를 한 번에 번역함 | 실행 시점에 코드를 한 줄씩 즉석에서 번역함 | 1차 컴파일 후, 실행 시점에 가상 머신이 번역함 |
| 실행 속도 | 매우 빠름 | 상대적으로 느림 | 중간 (JIT 컴파일러로 보완함) |
| 개발 속도 | 수정 시마다 재컴파일이 필요해 상대적으로 느림 | 실행 파일 생성 없이 즉시 확인이 가능해 빠름 | 컴파일 단계가 있으나, 가상 머신 덕분에 테스트가 용이함 |
| 하드웨어 독립성 | 종속적임 (CPU, OS별로 다르게 컴파일해야 함) | 독립적임 (인터프리터만 있으면 실행 가능함) | 독립적임 (가상 머신 위에서 동일하게 동작함) |
| 대표 언어 | C, C++, Rust, Go | Python, JavaScript, Ruby | Java, C# |

## 1.4 프로그래밍 패러다임
### 1.4.1 절차지향 프로그래밍 (Procedural Programming)
- 프로그램의 실행 순서, 즉 `절차`를 중요하게 여기며 데이터를 처리하는 함수(명령의 집합) 중심으로 작성하는 방식
- 데이터보다 함수(동작)가 중심이 되며, 정해진 순서대로 처리하는 것에 집중
- 특징
  + 컴퓨터의 처리 구조와 유사하여 실행 속도가 빠름
  + 프로그램의 흐름을 파악하기 쉬움
  + 데이터와 함수가 분리되어 있어, 데이터 구조가 변경되면 관련 함수를 모두 수정해야 하는 번거로움이 있음
- 대표 언어: C, Pascal, Fortran, COBOL

### 1.4.2 객체지향 프로그래밍 (Object-Oriented Programming, OOP)
- 데이터와 그 데이터를 처리하는 함수를 객체라는 하나의 단위로 묶어 관리하는 방식
- 실제 세계의 사물을 모델링하여 설계
- 특징
  + 코드 재사용성이 높고 유지보수가 쉬움
  + 설계 단계에 시간이 많이 소요되며, 절차지향에 비해 실행 속도가 상대적으로 느릴 수 있음
- 대표 언어: Java, C++, Python, C#

# 2. 자바(Java)의 탄생과 동작 방식
## 2.1 자바의 탄생
### 그린 프로젝트
- 1991년, 썬 마이크로시스템즈(Sun Microsystems)의 제임스 고슬링(James Gosling), 패트릭 노튼, 마이크 셰리던 등 '그린 팀'이라 불리는 소수의 엔지니어들이 모여 시작함

### 목표
- 가전제품(TV, 냉장고 등)들이 서로 연결되어 동작하는 `지능형 가전 네트워크`(현재의 스마트홈과 유사) 개발을 목표로 각 가전 제품의 하드웨어를 제어하는 플랫폼 구축

### 문제
- 가전제품마다 CPU 사양이 제각각이었고, 당시 주력 언어인 C++는 플랫폼마다 코드를 새로 짜야 하는 번거로움이 있었기 때문에 플랫폼 독립적이고 네트워크 통신에 최적화된 새로운 언어인 Java를 개발함

### 결과
- 프로젝트는 실패했지만 당시에 보급되기 시작한 인터넷 환경에서 강점을 보이는 Java의 애플릿이 주목을 받게 됨
- 애플릿 (Applet): 웹 브라우저에 포함되어 클라이언트 측에서 실행되는 소규모 자바 프로그램으로, HTML만으로 부족했던 동적인 기능(게임, 차트, 애니메이션 등)을 구현하기 위해 사용되었던 기술이지만 현재는 더이상 사용되지 않고 Javascript가 그 자리를 차지함

## 2.2 자바의 특징
- 슬로건: WORA(Write Once, Run Anywhere)
- 운영체제 독립성: JVM을 통해 어떤 플랫폼에서든 동일하게 실행 가능
- 순수 객체지향: 설계부터 객체지향 원칙을 철저히 따름
- 자동 메모리 관리(GC): 개발자가 직접 메모리를 해제할 필요 없이 가비지 컬렉터가 찌꺼기 메모리를 자동 청소
- 멀티스레드 지원: 언어 차원에서 강력한 멀티스레드 API를 제공

# 3 JVM의 동작 방식과 메모리

## 3.1 JVM (Java Virtual Machine) 구조
- 자바 프로그램은 OS가 직접 실행하지 않고, JVM이라는 가상 컴퓨터가 중간에서 실행해 줌

### 코드 실행 순서
1. 개발자가 `.java` 파일 작성
2. 컴파일러(`javac`)가 바이트코드(`.class`)로 변환
3. JVM의 클래스 로더가 `.class`를 메모리로 적재
4. 실행 엔진이 한 줄씩 읽으며 기계어로 변환하여 실행

## 3.2 실행 엔진 구성 요소

### 3.2.1 인터프리터
바이트코드(.class)를 한 줄씩 읽어서 네이티브 코드로 해석하고 즉시 실행

### 3.2.2 JIT (Just-In-Time) 컴파일러
인터프리터 방식으로 실행하다가, '핫 스팟(Hot Spot)'이라 불리는 자주 호출되는 코드 영역을 감지하면 해당 바이트코드 전체를 기계어로 컴파일하여 캐시에 저장하며, 이후에는 인터프리팅 없이 직접 실행됨

### 3.2.3 가비지 컬렉터
런타임 데이터 영역(Runtime Data Area)의 Heap 메모리를 관리하며, 더 이상 참조되지 않는 객체들을 식별하고 제거하여 메모리를 확보

## 3.3 JVM 메모리 구조
JVM은 운영체제로부터 메모리를 할당받아 세 구역으로 나누어 사용

<details>
<summary>상세 내용 펼치기</summary>

### 메서드 영역 (Method Area / Static Area)
- 클래스 설계도 정보, 상수, `static` 변수가 저장되는 공유 공간
- 프로그램 시작 시 할당되어 종료될 때까지 유지됨

### 스택 영역 (Stack Area)
- 메서드가 호출될 때마다 해당 메서드만의 작업 공간(스택 프레임)이 생성됨
- 내부의 지역 변수, 매개변수가 저장됨
- 메서드가 종료되면 메모리에서 즉시 해제 (LIFO 구조)

### 힙 영역 (Heap Area)
- `new` 키워드로 동적 생성되는 모든 객체(인스턴스)와 배열이 저장되는 거대한 공간
- 스택 영역의 변수들은 이 힙 영역의 메모리 주소만을 가리킴(참조)
- 어떤 변수에서도 참조하지 않는 객체는 가비지 컬렉터(GC)가 주기적으로 메모리에서 해제
</details>

# 4 개발 환경 구성
## 4.1 JRE와 JDK
### JRE (Java Runtime Environment)
- 자바 프로그램이 실행되기 위해서 필요한 환경
- JVM과 핵심 라이브러리 포함

### JDK (Java Development Kit)
- JRE를 포함하며, 컴파일러, 디버거 등 자바 개발에 필요한 도구가 들어있음
- javac: 자바 소스 파일(.java)을 바이트코드(.class)로 변환하는 컴파일러
- java: 컴파일된 바이트코드를 실행하는 인터프리터. 내부의 JVM(Java Virtual Machine)을 구동
- jar: 여러 클래스 파일과 리소스를 하나로 묶어 관리하는 압축 도구
- jdb: 프로그램의 오류를 찾고 수정하는 디버거

### LTS와 기능 릴리스(Feature Release)의 차이
- LTS(장기 지원 버전): 일반적인 버전보다 훨씬 더 긴 기간(보통 5년 이상) 동안 보안 패치와 버그 수정을 지원하는 버전을 의미. 실무 환경에서 서버 애플리케이션을 안정적으로 유지보수하기 위해 기업들은 주로 이 LTS 버전을 표준으로 채택하여 운영
- 기능 릴리스(Feature Release): 6개월 주기로 출시되는 일반 배포 버전으로, 다음 버전이 나오면 곧바로 지원이 종료됨. 자바의 새로운 문법이나 기능(프리뷰)을 빠르게 실험해 보기 위한 목적으로 주로 사용

## 3. 기본 자료형과 형변환
- 참고: https://docs.oracle.com/javase/tutorial/java/nutsandbolts/datatypes.html

### 3.1 변수와 상수
- 변수: 데이터를 담는 메모리 상의 빈 상자. 값 변경 가능
- 상수: 한 번 값이 들어가면 절대 못 바꾸는 불변의 상자. `final` 키워드 사용

```java
int age = 25;      // 변수 선언 및 초기화
age = 26;          // 값 변경 가능

final int MAX_SIZE = 100; // 상수 선언 (주로 대문자와 언더스코어 사용)
// MAX_SIZE = 200; // 에러 발생! 상수는 변경 불가
```

### 3.2 기본 자료형의 종류
총 8가지로 메모리에 실제 값을 직접 저장.

#### 정수형
- `byte` (1 byte): -128 ~ 127
- `short` (2 byte): -32,768 ~ 32,767
- `int` (4 byte): 약 -21억 ~ 21억 (자바 정수 기본 타입)
- `long` (8 byte): 엄청 큰 숫자 (끝에 `L` 또는 `l`을 붙임)

#### 실수형
- `float` (4 byte): 소수점 7자리 정밀도 (끝에 `F` 또는 `f` 붙임)
- `double` (8 byte): 소수점 15자리 정밀도 (자바 실수 기본 타입)

#### 논리형과 문자형
- `boolean` (1 byte): `true` 또는 `false`만 가짐
- `char` (2 byte): 홑따옴표로 문자 단 하나만 저장. 내부적으로는 유니코드 숫자로 저장됨

```java
int num = 10;
long bigNum = 3000000000L; // L을 안붙이면 int로 인식해 에러남
double pi = 3.14159;
float smallPi = 3.14F;     // F 안붙이면 double로 인식해 에러남
boolean isGood = true;
char grade = 'A';
```

### 3.3 참조 자료형(Reference Type)과 String
- 기본 자료형 8개를 제외한 모든 자료형(배열, 클래스, 인터페이스 등)은 참조 자료형임
- 실제 값은 힙 메모리에 저장하고, 변수에는 힙 메모리의 주소값을 저장
- `String`은 문자열을 다루는 클래스이며 참조 자료형
- `String` 리터럴은 힙 메모리 내의 String Constant Pool이라는 특별한 공간에 저장되어 재사용성을 높임

```java
String name1 = '멋쟁이';
String name2 = '멋쟁이'; // name1과 같은 주소를 참조
String name3 = new String('멋쟁이'); // 새로운 객체를 힙에 생성
```

### 3.4 형변환(Type Casting)
서로 다른 타입끼리 연산하거나 대입할 때 크기를 맞춰주는 작업.

#### 자동 형변환 (묵시적 형변환)
- 작은 크기의 타입을 큰 크기의 타입으로 변환할 때 발생 (데이터 손실 없음)
- `byte` -> `short` -> `int` -> `long` -> `float` -> `double`

```java
int a = 10;
double b = a; // int가 double로 자동 변환. b는 10.0이 됨
```

#### 강제 형변환 (명시적 형변환)
- 큰 크기의 타입을 작은 크기의 타입으로 강제 변환할 때 발생 (데이터 손실 위험)
- 괄호 `(타입)`를 명시해야 함

```java
double pi = 3.14;
int p = (int) pi; // 강제로 소수점을 버림. p는 3이 됨 (데이터 손실)
```

## 4. 연산자와 제어 흐름 설계

### 4.1 산술 및 대입 연산자
- 산술 연산자: `+`, `-`, `*`, `/`, `%`(나머지)
- 문자열의 `+` 연산은 문자열 결합을 의미
- 대입 연산자: `=`, `+=`, `-=`, `*=`, `/=`, `%=`

```java
int count = 0;
count += 5; // count = count + 5 와 동일
int result = count % 4; // 5 나누기 4의 나머지인 1
```

### 4.2 증감 및 비교 연산자
- 증감 연산자: `++`, `--`
- 변수 앞에 붙으면 연산 전 증감, 뒤에 붙으면 연산 후 증감
- 비교 연산자: `==`(같다), `!=`(다르다), `>`, `<`, `>=`, `<=`

```java
int a = 10;
int b = a++; // b에는 10이 들어가고, 그 후 a가 11이 됨
int c = ++a; // a가 먼저 12가 되고, c에 12가 들어감
boolean isEqual = (a == c); // true
```

### 4.3 논리 및 삼항 연산자
- 논리 연산자: `&&`(AND), `||`(OR), `!`(NOT)
- 삼항 연산자: `조건식 ? 참일_때_값 : 거짓일_때_값`

```java
int score = 85;
String result = (score >= 80) ? '합격' : '불합격'; // 합격 반환
```

### 4.4 조건문(if, switch)
#### if-else 문
- 조건식의 참/거짓에 따라 블록을 실행

```java
int age = 20;

if (age >= 20) {
  System.out.println('성인');
} else if (age >= 14) {
  System.out.println('청소년');
} else {
  System.out.println('어린이');
}
```

#### switch 문
- 변수 값에 따라 즉시 해당 `case`로 점프
- `break`를 작성하지 않으면 아래의 case까지 모두 실행되므로 주의해야 함 (자바 14부터는 새로운 switch 표현식이 추가됨)

```java
String role = 'ADMIN';

switch (role) {
  case 'ADMIN':
    System.out.println('관리자 권한');
    break;
  case 'USER':
    System.out.println('일반 사용자');
    break;
  default:
    System.out.println('권한 없음');
}
```

### 4.5 반복문(for, while, do-while)
#### for 문
- 반복 횟수가 명확할 때 주로 사용
- `for (초기화; 조건식; 증감식) { ... }`

```java
for (int i = 0; i < 5; i++) {
  System.out.println('현재 숫자: ' + i); // 0부터 4까지 5번 출력
}
```

#### while과 do-while 문
- `while`은 조건이 참인 동안 반복
- `do-while`은 조건을 나중에 검사하므로 최소 1번의 실행을 보장

```java
int i = 0;
while (i < 3) {
  System.out.println('while 루프: ' + i);
  i++; 
}

int j = 10;
do {
  System.out.println('do-while 무조건 한번은 실행됨: ' + j);
} while (j < 5); // 거짓이지만 위에서 이미 한번 출력됨
```

#### break와 continue
- `break`: 실행되는 순간 소속된 반복문 자체를 종료하고 탈출
- `continue`: 이번 턴만 건너뛰고 다음 턴으로 바로 넘어감

## 5. 배열과 메모리 관리

### 5.1 배열의 개념과 선언
- 배열이란 같은 타입의 데이터 여러 개를 하나로 묶어서 관리하는 바구니
- 정적 할당: 자바의 배열은 처음에 크기를 정하면 나중에 절대 늘리거나 줄일 수 없음
- 배열 자체는 객체이므로 JVM 힙 영역에 생성되며 `new` 연산자를 사용해야 함

```java
// 선언과 동시에 5칸짜리 빈 배열 생성 (정수 기본값 0으로 채워짐)
int[] scores = new int[5]; 

// 값 넣기 (인덱스는 0부터 시작!)
scores[0] = 100;
scores[1] = 90;

// 선언과 동시에 데이터 채워넣기 (초기화)
String[] names = {'김사자', '이멋쟁', '박백엔드'};
```

### 5.2 다차원 배열
- 2차원 이상의 배열을 의미하며 행렬 구조와 비슷
- 자바에서는 배열의 배열 개념으로 처리됨

```java
int[][] matrix = new int[2][3]; // 2행 3열 배열
matrix[0][0] = 1;
matrix[1][2] = 5;

// 초기화와 동시에 생성
int[][] arr = {
  {1, 2, 3},
  {4, 5, 6}
};
```

### 5.3 향상된 for문
- 배열이나 리스트의 모든 요소를 처음부터 끝까지 순회할 때 인덱스 없이 편리하게 사용하는 문법

```java
int[] numbers = {10, 20, 30};

// 향상된 for문
for (int num : numbers) {
  System.out.println(num);
}
```

### 5.4 배열의 복사와 Arrays 클래스
- 배열은 크기를 변경할 수 없으므로 더 큰 배열을 만들고 기존 값을 복사하는 방식을 사용
- `System.arraycopy()`나 `Arrays.copyOf()`를 활용

```java
import java.util.Arrays;

int[] original = {1, 2, 3};
int[] copied = Arrays.copyOf(original, 5); // [1, 2, 3, 0, 0]
```

## 6. 모듈화와 메서드(Method)

### 6.1 메서드의 구조와 반환타입
- 특정 기능(코드 블록)을 하나로 묶어놓은 것
- 중복되는 코드를 복붙하지 않고, 메서드로 만들어두면 재사용 가능

```java
// 접근제어자 반환타입 메서드명(매개변수)
public int add(int a, int b) {
  int sum = a + b;
  return sum; // 결과값 반환
}
```
- 반환할 게 없으면 반환타입에 `void`를 씀

### 6.2 메서드 오버로딩
- 한 클래스 안에서 메서드 이름은 똑같이 하되, 매개변수(개수나 타입)를 다르게 여러 개 만드는 것
- 사용자의 편의성을 극대화함

```java
public int multiply(int a, int b) { return a * b; }
public double multiply(double a, double b) { return a * b; }
public int multiply(int a, int b, int c) { return a * b * c; }
```

### 6.3 가변 인자(varargs)
- 매개변수의 개수를 동적으로 지정할 수 있는 기능
- 내부적으로는 배열로 처리됨
- 가변 인자는 매개변수 목록의 가장 마지막에만 위치할 수 있음

```java
public void printNumbers(int... nums) {
  for (int num : nums) {
    System.out.println(num);
  }
}
// 호출: printNumbers(1, 2, 3);
// 호출: printNumbers(10, 20);
```

## 7. 객체지향 프로그래밍(OOP) 기초

### 7.1 클래스와 인스턴스
- 클래스(Class): 붕어빵 틀. 객체를 만들기 위한 설계도이며 메모리에 실체는 없음
- 인스턴스(Instance): 붕어빵. 설계도를 바탕으로 `new` 연산자를 통해 힙 메모리에 구워져 나온 실제 결과물(객체)

### 7.2 클래스의 구성 요소
1. 필드 (Field): 객체의 상태, 속성 (변수)
2. 메서드 (Method): 객체의 동작, 행위 (함수)
3. 생성자 (Constructor): 객체가 `new`로 생성될 때 초기 세팅을 담당

```java
public class Car {
  String model;
  int speed;

  // 생성자 (반환 타입 없음)
  public Car(String model) {
    this.model = model;
    this.speed = 0;
  }

  public void accelerate() {
    this.speed += 10;
    System.out.println(model + ' 속도 증가! 현재 속도: ' + speed);
  }
}
```

### 7.3 this와 this()
- `this`: 생성된 자기 자신 객체를 가리키는 참조 변수. 매개변수와 필드명이 같을 때 구별하기 위해 사용
- `this()`: 같은 클래스 내의 다른 생성자를 호출할 때 사용. 생성자 내부의 첫 줄에만 작성 가능

```java
public class User {
  String name;
  int age;

  public User() {
    this('기본이름', 1); // 다른 생성자 호출
  }

  public User(String name, int age) {
    this.name = name;
    this.age = age;
  }
}
```

### 7.4 패키지와 임포트
- 패키지: 관련된 클래스들을 그룹화하는 폴더 구조
- 임포트(`import`): 다른 패키지에 있는 클래스를 사용할 때 명시

### 7.5 캡슐화와 접근 제어자
- 캡슐화: 중요한 데이터를 외부에서 임의로 변경하지 못하도록 은닉하는 기법
- 접근 제어자: `private` < `default` < `protected` < `public`
- 필드를 `private`으로 선언하고 Getter/Setter 메서드를 통해 접근을 제어

```java
public class Account {
  private int balance; // 외부 접근 차단

  public int getBalance() {
    return this.balance;
  }

  public void deposit(int amount) {
    if (amount > 0) {
      this.balance += amount;
    }
  }
}
```

### 7.6 정적(static) 멤버
- `static` 키워드가 붙은 필드나 메서드는 인스턴스 생성을 하지 않아도 클래스명으로 바로 접근 가능
- 모든 인스턴스가 공유하는 메모리(메서드 영역)에 저장됨

```java
public class MathUtils {
  public static final double PI = 3.14159;
  
  public static int add(int a, int b) {
    return a + b;
  }
}
// 호출: MathUtils.add(10, 20);
```

## 8. 객체지향 심화 - 상속(Inheritance)

### 8.1 상속의 개념
- 기존 부모 클래스의 필드와 메서드를 자식 클래스가 그대로 물려받아 확장하는 것
- 자바는 단일 상속만 지원 (`extends` 사용)
- 코드의 중복을 제거하고 다형성을 구현하는 기반이 됨

```java
public class Animal {
  public void eat() {
    System.out.println('냠냠 먹는다');
  }
}

public class Dog extends Animal {
  public void bark() {
    System.out.println('멍멍!');
  }
}
```

### 8.2 메서드 오버라이딩
- 부모 클래스에게 상속받은 메서드를 자식 클래스에서 재정의하는 것
- `@Override` 애노테이션을 붙여주면 컴파일러가 검증해줌

```java
public class Cat extends Animal {
  @Override
  public void eat() {
    System.out.println('츄르를 먹는다'); 
  }
}
```

### 8.3 super와 super()
- `super`: 부모 객체의 필드나 메서드에 접근할 때 사용
- `super()`: 부모 생성자를 호출. 자식 생성자의 첫 줄에 반드시 부모 생성자가 호출되어야 함

### 8.4 final 키워드
- 변수: 상수가 되어 값 변경 불가
- 메서드: 자식 클래스에서 오버라이딩 불가
- 클래스: 상속 불가 (예: `String` 클래스는 `final`로 선언되어 있음)

### 8.5 Object 클래스
- 자바의 모든 클래스는 암묵적으로 `java.lang.Object` 클래스를 상속받음
- 주요 메서드: `toString()`, `equals()`, `hashCode()`

## 9. 객체지향 심화 - 다형성(Polymorphism)과 인터페이스

### 9.1 다형성과 업캐스팅/다운캐스팅
- 하나의 부모 타입 변수로 여러 자식 객체를 다룰 수 있는 특징
- 업캐스팅: 자식 객체를 부모 타입에 담는 것 (자동 형변환)
- 다운캐스팅: 부모 타입에 담긴 객체를 다시 자식 타입으로 돌려놓는 것 (명시적 형변환 필요)

```java
Animal myPet = new Dog(); // 업캐스팅
myPet.eat(); // Dog의 오버라이딩된 eat() 실행
// myPet.bark(); // 에러 발생

Dog realDog = (Dog) myPet; // 다운캐스팅
realDog.bark(); // 정상 작동
```

### 9.2 instanceof 연산자
- 참조 변수가 실제로 어떤 타입의 객체를 가리키고 있는지 확인할 때 사용

```java
if (myPet instanceof Cat) {
  Cat myCat = (Cat) myPet;
  myCat.meow();
}
```

### 9.3 추상 클래스
- 미완성 설계도. 구현부가 없는 추상 메서드를 포함할 수 있음
- 자기가 직접 `new`로 객체가 될 수 없음

```java
public abstract class Shape {
  public abstract void draw(); // 구현 강제
}
```

### 9.4 인터페이스의 개념과 구현
- 객체가 수행해야 할 동작의 규격만을 정의
- 다중 구현(`implements`)이 가능

```java
public interface Flyable {
  void fly();
}

public class Bird extends Animal implements Flyable {
  @Override
  public void fly() {
    System.out.println('파닥파닥 날아감');
  }
}
```

### 9.5 인터페이스의 디폴트 메서드
- 자바 8부터 인터페이스에 구현부를 가진 `default` 메서드를 정의할 수 있게 됨
- 기존 코드를 깨뜨리지 않고 인터페이스를 확장할 때 유용함

## 10. 자료 구조와 컬렉션 프레임워크(Collection)

### 10.1 컬렉션 프레임워크 구조
- 배열의 크기 고정 문제를 해결하고 동적 크기 변경, 정렬 등의 기능을 제공하는 자료구조 모음집
- 핵심 인터페이스: List, Set, Map

### 10.2 List 인터페이스(ArrayList, LinkedList)
- 순서가 유지되고 중복을 허용
- `ArrayList`: 내부적으로 배열을 사용. 인덱스 조회가 빠르지만 데이터 삽입/삭제 시 이동 작업으로 인해 느림
- `LinkedList`: 노드들이 체인처럼 연결된 구조. 데이터 삽입/삭제가 빠르지만 인덱스 조회가 느림

```java
List<String> list = new ArrayList<>();
list.add('Java');
list.add('Spring');
System.out.println(list.get(1)); // Spring
```

### 10.3 Set 인터페이스(HashSet, TreeSet)
- 순서를 유지하지 않으며 중복 저장을 허용하지 않음
- `HashSet`: 해시 알고리즘 기반. 검색 속도가 가장 빠름
- `TreeSet`: 이진 탐색 트리 기반. 데이터가 자동 정렬되어 저장됨

```java
Set<Integer> set = new HashSet<>();
set.add(10);
set.add(10); // 중복 무시됨
System.out.println(set.size()); // 1
```

### 10.4 Map 인터페이스(HashMap, TreeMap)
- 키와 값의 쌍(Key-Value)으로 데이터를 저장
- 키는 중복 불가, 값은 중복 가능

```java
Map<String, Integer> map = new HashMap<>();
map.put('사과', 1000);
map.put('사과', 1500); // 덮어씌워짐
System.out.println(map.get('사과')); // 1500
```

### 10.5 제네릭(Generic)
- 컬렉션에 들어갈 데이터 타입을 컴파일 시점에 지정하여 타입 안정성을 높이는 문법

## 11. 모던 자바 - 람다(Lambda)와 함수형 프로그래밍

### 11.1 함수형 프로그래밍이란?
- 상태 변경을 피하고 순수 함수를 조합하여 프로그램을 작성하는 패러다임
- 자바 8부터 람다식을 통해 함수를 일급 객체처럼 다룰 수 있게 됨

### 11.2 람다식 문법
- 메서드의 이름과 반환타입을 생략하고 화살표 `->` 를 이용
- `(매개변수) -> { 실행문; }`

```java
// 기존 익명 클래스
Runnable r1 = new Runnable() {
  @Override
  public void run() {
    System.out.println('달린다');
  }
};

// 람다식 적용
Runnable r2 = () -> System.out.println('달린다');
```

### 11.3 표준 함수형 인터페이스
자바 라이브러리(`java.util.function`)에서 자주 쓰이는 패턴을 미리 정의해 두었음.
- `Predicate<T>`: 매개변수를 받아 `boolean`을 반환
- `Consumer<T>`: 매개변수를 받아서 소모만 하고 반환하지 않음 (`void`)
- `Function<T, R>`: 매개변수를 받아서 다른 타입으로 변환하여 반환
- `Supplier<T>`: 매개변수 없이 값을 제공

### 11.4 메서드 참조
- 람다식이 단 하나의 메서드만 호출할 때 코드를 더 간결하게 줄이는 문법 `클래스명::메서드명`

```java
// 람다
Consumer<String> printer = s -> System.out.println(s);
// 메서드 참조
Consumer<String> betterPrinter = System.out::println;
```

## 12. 데이터 가공 - 스트림(Stream) API

### 12.1 스트림 API 개념
- 컬렉션의 데이터들을 파이프라인 형태로 연결하여 필터링, 매핑 등의 처리를 선언형으로 작성하는 기능

### 12.2 스트림 파이프라인 3단계
1. 생성: 컬렉션이나 배열에서 스트림을 엶
2. 중간 연산: 데이터를 필터링하거나 변환함 (여러 개 연결 가능)
3. 최종 연산: 결과를 모으거나 순회하며 스트림을 닫음

### 12.3 주요 중간 연산
- `filter()`: 조건에 맞는 요소만 남김
- `map()`: 요소를 다른 형태로 변환
- `flatMap()`: 중첩된 구조를 평탄화
- `sorted()`: 요소를 정렬
- `distinct()`: 중복을 제거

### 12.4 주요 최종 연산
- `forEach()`: 각 요소를 순회하며 소비
- `collect()`: 결과를 리스트나 맵 등으로 변환하여 수집
- `count()`, `sum()`, `max()`, `min()`: 집계 연산을 수행

```java
List<String> names = Arrays.asList('Kim', 'Park', 'Lee', 'Kang', 'Koo');

List<String> result = names.stream()               
  .filter(name -> name.startsWith('K'))          
  .map(String::toUpperCase)               
  .collect(Collectors.toList());                 

System.out.println(result); // [KIM, KANG, KOO]
```

### 12.5 지연 연산(Lazy Evaluation)
- 최종 연산이 호출되기 전까지 중간 연산은 실행을 미루며 대기
- 최종 연산이 호출될 때 최적의 경로로 한 번에 처리하여 성능을 높임

## 13. 예외 처리(Exception)

### 13.1 에러와 예외
- 에러(Error): 메모리 부족 등 프로그램 코드로 수습할 수 없는 심각한 시스템 문제
- 예외(Exception): 프로그램 코드로 수습 가능한 비교적 덜 심각한 오류

### 13.2 예외 클래스의 계층 구조
- 모든 예외의 최고 조상은 `Exception` 클래스
- `RuntimeException`과 그 하위 클래스(Unchecked 예외): 컴파일러가 예외 처리를 강제하지 않음
- 그 외의 `Exception` (Checked 예외): 반드시 `try-catch`로 묶어주거나 예외를 전가해야 컴파일됨

### 13.3 try-catch-finally 블록
```java
try {
  int result = 10 / 0; // 예외 발생
} catch (ArithmeticException e) {
  System.out.println('0으로 나눌 수 없음');
} finally {
  System.out.println('예외 발생 여부와 상관없이 무조건 실행됨');
}
```

### 13.4 throws와 throw
- `throws`: 메서드 선언부에 사용하여, 이 메서드에서 발생할 수 있는 예외를 호출한 곳으로 떠넘김
- `throw`: 개발자가 고의로 예외 객체를 생성하여 발생시킴

### 13.5 사용자 정의 예외
- 비즈니스 로직에 맞는 구체적인 예외 상황을 표현하기 위해 커스텀 예외 클래스를 만들 수 있음

## 14. 소프트웨어 품질과 TDD 철학

### 14.1 단위 테스트(Unit Test)
- 작성한 코드가 의도대로 동작하는지 가장 작은 단위로 쪼개어 검증하는 것
- 부작용을 조기 발견하고 리팩토링 시 안전망 역할을 함

### 14.2 JUnit 프레임워크 기초
- 자바 생태계의 표준 테스트 프레임워크
- `@Test`, `@BeforeEach`, `@AfterEach`, `@DisplayName` 등의 애노테이션을 활용

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

public class CalculatorTest {
  @Test
  void 더하기_테스트() {
    Calculator calc = new Calculator();
    int result = calc.add(2, 3);
    assertEquals(5, result);
  }
}
```

### 14.3 TDD 3단계 사이클
- TDD는 실제 코드 작성 전 실패하는 테스트를 먼저 작성하는 개발 방법론
1. RED: 구현할 기능에 대해 실패하는 테스트 코드를 작성
2. GREEN: 테스트를 통과하기 위한 최소한의 코드를 작성
3. REFACTOR: 테스트 통과를 유지하며 코드를 개선

### 14.4 TDD를 도입하는 이유와 아키텍처
- 테스트하기 쉬운 코드를 작성하려 노력하면, 자연스럽게 클래스 간 결합도가 낮아지고 응집도가 높은 유연한 아키텍처가 도출됨
- TDD는 단순한 테스트 기술이 아니라 좋은 객체지향 설계를 유도하는 설계 기법
