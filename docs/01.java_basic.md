# 1. 프로그래밍의 이해

## 1.1 프로그래밍이란?
- 프로그램이란 컴퓨터에 내리는 명령의 집합이고 이를 만드는 과정을 프로그래밍이라고 함
- 컴퓨터의 CPU는 0과 1로 이루어진 기계어만 이해할 수 있는 단순한 연산 장치
- 컴퓨터에게 명령을 내리기 위해 인간이 0과 1로 구성된 기계어를 직접 작성하기는 매우 어렵기 때문에 인간이 이해하기 쉽도록 인간의 언어와 유사한 프로그래밍 언어(고급 언어)를 만들어서 사용
- 대표적인 프로그래밍 언어로 C, Java, Python, Javascript 등이 있음
- 고급 언어로 만들어진 코드를 `소스 코드`라고 함
- 소스 코드는 인간이 이해 가능하지만 컴퓨터가 이해할 수 없으므로 컴퓨터가 이해할 수 있는 `기계어`로 변환해야 하는데 이 과정을 컴파일 또는 인터프리팅이라 함

## 1.2 컴파일러와 인터프리터
- 컴파일: 개발자가 작성한 소스 코드를 컴퓨터가 이해할 수 있는 기계어로 한 번에 번역하는 과정
- 컴파일러: 컴파일을 수행하는 프로그램
- 인터프리팅: 소스 코드를 한 줄씩 읽어가며 기계어로 즉석에서 번역하는 과정
- 인터프리터: 인터프리팅을 수행하고 그 결과를 즉시 실행하는 프로그램

## 1.3 컴파일러 언어 vs. 인터프리터 언어
### 1.3.1 컴파일러(Compiler) 언어
- 코드를 실행하기 전, 전체 소스 코드를 한 번에 기계어로 번환(컴파일)하여 실행 파일을 만드는 방식
- 특징
  + 실행 속도가 매우 빠르지만, 코드를 수정할 때마다 다시 컴파일해야 하므로 개발 속도는 상대적으로 느릴 수 있음
  + CPU 아키텍처마다 사용하는 명령어 집합이 다르기 때문에 그에 맞게 기계어가 생성되어야 하고, 프로그램이 메모리를 할당받거나 화면에 글자를 출력할 때 OS에 요청을 보내는 `시스템 콜`이 OS마다 다름. 결과적으로 컴파일된 결과물은 특정 플랫폼(CPU + OS)에 종속됨
- 대표적인 언어
  + C / C++: 시스템 프로그래밍이나 게임 엔진 개발에 주로 쓰이며 성능이 매우 강력함
  + Rust: 메모리 안전성을 보장하면서도 C++에 준하는 성능을 내어 최근 각광받고 있음
  + Go (Golang): 구글에서 개발했으며, 컴파일 속도가 빠르고 병렬 처리에 강점이 있음

### 1.3.2 인터프리터(Interpreter) 언어
- 코드를 실행할 때 전체를 미리 번역하지 않고, 한 줄씩 읽어가며 즉석에서 기계어로 번역과 실행을 동시에 수행하는 방식
- 특징
  + 실행 파일을 미리 만들지 않으므로 코드를 수정한 후 즉각적인 확인이 가능해 개발 속도가 빠름
  + 코드를 실행할 때마다 매번 번역을 거쳐야 하므로 컴파일러 언어에 비해 실행 속도는 상대적으로 느림
  + 각 운영체제에 맞는 인터프리터만 설치되어 있으면 동일한 코드를 어디서든 실행할 수 있어 플랫폼에 독립적
- 대표적인 언어
  + Python: 문법이 직관적이고 간결하여 기초 교육부터 데이터 분석, 인공지능 분야까지 폭넓게 쓰임
  + JavaScript: 웹 브라우저에서 동작하는 유일한 언어로 시작해, 현재는 프론트엔드와 백엔드를 아우르는 거대한 생태계를 가짐
  + Ruby: 개발자의 생산성을 극대화하는 데 초점을 맞춘 언어로, 웹 프레임워크인 Ruby on Rails를 통해 널리 쓰임

### 1.3.3 하이브리드(Hybrid) 언어
- 소스 코드를 바이트코드(중간어)로 1차 컴파일한 뒤, 실행 시점에 가상 머신(VM)을 통해 기계어로 번역하며 실행하는 혼합 방식
- 특징
  + 컴파일 단계를 통해 실행 전에 문법 오류를 잡을 수 있고, 가상 머신이 실행 환경에 맞게 번역해주므로 운영체제에 독립적
  + 인터프리터의 느린 속도를 보완하기 위해 JIT 컴파일러 등을 활용하여 자주 쓰이는 코드를 기계어로 캐싱
- 대표적인 언어
  + Java: 가상 머신(JVM, Java Virtual Machine) 위에서 동작하며, 엔터프라이즈급 백엔드 서버 개발에 전 세계적으로 가장 많이 쓰이는 언어임
  + C#: 마이크로소프트 환경과 닷넷(.NET) 환경에서 구동되며, 특히 게임 개발 등에서 뛰어난 생산성과 성능을 발휘

### 1.3.4 세 방식의 언어 비교 요약

| 구분 | 컴파일러 언어 | 인터프리터 언어 | 하이브리드 언어 |
| :--- | :--- | :--- | :--- |
| 동작 방식 | 실행 전 전체 소스 코드를 한 번에 번역함 | 실행 시점에 코드를 한 줄씩 즉석에서 번역함 | 1차 컴파일 후, 실행 시점에 가상 머신이 번역함 |
| 실행 속도 | 매우 빠름 | 상대적으로 느림 | 중간 (JIT 컴파일러로 보완함) |
| 개발 속도 | 수정 시마다 재컴파일이 필요해 상대적으로 느림 | 실행 파일 생성 없이 즉시 확인이 가능해 빠름 | 컴파일 단계가 있으나, 가상 머신 덕분에 테스트가 용이함 |
| 하드웨어 독립성 | 종속적임 (CPU, OS별로 다르게 컴파일해야 함) | 독립적임 (인터프리터만 있으면 실행 가능함) | 독립적임 (가상 머신 위에서 동일하게 동작함) |
| 대표 언어 | C, C++, Rust, Go | Python, JavaScript, Ruby | Java, C# |

## 1.4 프로그래밍 패러다임
### 1.4.1 절차지향 프로그래밍 (Procedural Programming)
- 프로그램의 실행 순서, 즉 `절차`를 중요하게 여기며 데이터를 처리하는 함수(명령의 집합) 중심으로 작성하는 방식
- 데이터보다 함수(동작)가 중심이 되며, 정해진 순서대로 처리하는 것에 집중
- 특징
  + 컴퓨터의 처리 구조와 유사하여 실행 속도가 빠름
  + 프로그램의 흐름을 파악하기 쉬움
  + 데이터와 함수가 분리되어 있어, 데이터 구조가 변경되면 관련 함수를 모두 수정해야 하는 번거로움이 있음
- 대표 언어: C, Pascal, Fortran, COBOL

### 1.4.2 객체지향 프로그래밍 (Object-Oriented Programming, OOP)
- 데이터와 그 데이터를 처리하는 함수를 객체라는 하나의 단위로 묶어 관리하는 방식
- 실제 세계의 사물을 모델링하여 설계
- 특징
  + 코드 재사용성이 높고 유지보수가 쉬움
  + 설계 단계에 시간이 많이 소요되며, 절차지향에 비해 실행 속도가 상대적으로 느릴 수 있음
- 대표 언어: Java, C++, Python, C#

# 2. 자바(Java)의 탄생과 동작 방식
## 2.1 자바의 탄생
### 2.1.1 그린 프로젝트
- 1991년, 썬 마이크로시스템즈(Sun Microsystems)의 제임스 고슬링(James Gosling), 패트릭 노튼, 마이크 셰리던 등 '그린 팀'이라 불리는 소수의 엔지니어들이 모여 시작함

### 2.1.2 목표
- 가전제품(TV, 냉장고 등)들이 서로 연결되어 동작하는 `지능형 가전 네트워크`(현재의 스마트홈과 유사) 개발을 목표로 각 가전 제품의 하드웨어를 제어하는 플랫폼 구축

### 2.1.3 문제
- 가전제품마다 CPU 사양이 제각각이었고, 당시 주력 언어인 C++는 플랫폼마다 코드를 새로 짜야 하는 번거로움이 있었기 때문에 플랫폼 독립적이고 네트워크 통신에 최적화된 새로운 언어인 Java를 개발함

### 2.1.4 결과
- 프로젝트는 실패했지만 당시에 보급되기 시작한 인터넷 환경에서 강점을 보이는 Java의 애플릿이 주목을 받게 됨
- 애플릿 (Applet): 웹 브라우저에 포함되어 클라이언트 측에서 실행되는 소규모 자바 프로그램으로, HTML만으로 부족했던 동적인 기능(게임, 차트, 애니메이션 등)을 구현하기 위해 사용되었던 기술이지만 현재는 더이상 사용되지 않고 Javascript가 그 자리를 차지함

## 2.2 자바의 특징
- 슬로건: WORA(Write Once, Run Anywhere)
- 운영체제 독립성: JVM을 통해 어떤 플랫폼에서든 동일하게 실행 가능
- 순수 객체지향: 설계부터 객체지향 원칙을 철저히 따름
- 자동 메모리 관리(GC): 개발자가 직접 메모리를 해제할 필요 없이 가비지 컬렉터가 찌꺼기 메모리를 자동 청소
- 멀티스레드 지원: 언어 차원에서 강력한 멀티스레드 API를 제공

# 3. JVM의 동작 방식과 메모리

## 3.1 JVM (Java Virtual Machine) 구조
- 자바 프로그램은 OS가 직접 실행하지 않고, JVM이라는 가상 컴퓨터가 중간에서 실행해 줌

### 3.1.1 코드 실행 순서
1. 개발자가 `.java` 파일 작성
2. 컴파일러(`javac`)가 바이트코드(`.class`)로 변환
3. JVM의 클래스 로더가 `.class`를 메모리로 적재
4. 실행 엔진이 한 줄씩 읽으며 기계어로 변환하여 실행

---

## 3.2 실행 엔진 구성 요소

### 3.2.1 인터프리터
바이트코드(.class)를 한 줄씩 읽어서 네이티브 코드로 해석하고 즉시 실행

### 3.2.2 JIT (Just-In-Time) 컴파일러
인터프리터 방식으로 실행하다가, '핫 스팟(Hot Spot)'이라 불리는 자주 호출되는 코드 영역을 감지하면 해당 바이트코드 전체를 기계어로 컴파일하여 캐시에 저장하며, 이후에는 인터프리팅 없이 직접 실행됨

### 3.2.3 가비지 컬렉터
런타임 데이터 영역(Runtime Data Area)의 Heap 메모리를 관리하며, 더 이상 참조되지 않는 객체들을 식별하고 제거하여 메모리를 확보

## 3.3 JVM 메모리 구조
JVM은 운영체제로부터 메모리를 할당받아 세 구역으로 나누어 사용

<details>
<summary>상세 내용 펼치기</summary>

### 3.3.1 메서드 영역 (Method Area / Static Area)
- 클래스 설계도 정보, 상수, `static` 변수가 저장되는 공유 공간
- 프로그램 시작 시 할당되어 종료될 때까지 유지됨

### 3.3.2 스택 영역 (Stack Area)
- 메서드가 호출될 때마다 해당 메서드만의 작업 공간(스택 프레임)이 생성됨
- 내부의 지역 변수, 매개변수가 저장됨
- 메서드가 종료되면 메모리에서 즉시 해제 (LIFO 구조)

### 3.3.3 힙 영역 (Heap Area)
- `new` 키워드로 동적 생성되는 모든 객체(인스턴스)와 배열이 저장되는 거대한 공간
- 스택 영역의 변수들은 이 힙 영역의 메모리 주소만을 가리킴(참조)
- 어떤 변수에서도 참조하지 않는 객체는 가비지 컬렉터(GC)가 주기적으로 메모리에서 해제
</details>

# 4. 개발 환경 구성

### 4.1.1 JRE (Java Runtime Environment)
- 자바 프로그램이 실행되기 위해서 필요한 환경
- JVM과 핵심 라이브러리 포함

### 4.1.2 JDK (Java Development Kit)
- JRE를 포함하며, 컴파일러, 디버거 등 자바 개발에 필요한 도구가 들어있음

- java: 컴파일된 바이트코드를 실행하는 인터프리터. 내부의 JVM(Java Virtual Machine)을 구동

- 기능 릴리스(Feature Release): 6개월 주기로 출시되는 일반 배포 버전으로, 다음 버전이 나오면 곧바로 지원이 종료됨. 자바의 새로운 문법이나 기능(프리뷰)을 빠르게 실험해 보기 위한 목적으로 주로 사용

# 5. 데이터 타입과 변수

## 5.1 기본 데이터 타입(Primitive Type)
- primitive: "원초적인, 기초적인, 가장 기본적인" 이라는 뜻
- 프로그래밍에서 더 이상 쪼갤 수 없는 가장 기본 단위의 데이터 타입을 의미

#### 1) 정수형
- `byte` (1 byte): -2^7 ~ 2^7-1 (-128 ~ 127)
- `short` (2 byte): -2^15 ~ 2^15-1 (-32,768 ~ 32,767)
- `int` (4 byte): -2^31 ~ 2^31-1 (약 -21억 ~ 21억, 자바 정수 기본 타입)
- `long` (8 byte): -2^63 ~ 2^63-1 (약 -9.22E18 ~ 9.22E18, 끝에 `L` 또는 `l`을 붙임)

#### 2) 실수형
- `float` (4 byte): 유효 숫자 7자리 정밀도 (정수부 포함, 끝에 `F` 또는 `f` 붙임)
- `double` (8 byte): 유효 숫자 15자리 정밀도 (정수부 포함, 자바 실수 기본 타입)

#### 3) 논리형과 문자형
- `boolean` (1 byte): `true` 또는 `false`만 가짐
- `char` (2 byte): 홑따옴표로 문자 하나만 저장. 내부적으로는 유니코드(UTF-16) 숫자로 저장됨

## 5.2 참조 데이터 타입(Reference Type)
- 기본 데이터 타입 8개를 제외한 모든 데이터 타입(배열, 클래스 등)은 참조 데이터 타입임
- 객체가 메모리 상에 실제 올라가 있는 위치 주소(Reference)를 가리키는 방식으로 작동함

## 5.3 변수와 상수
### 5.3.1 변수의 어원
#### 1) variable (변수)
- "var": 라틴어 'varius'에서 유래, '다르다', '변하다'라는 의미
- "able": "~할 수 있는", "~의 능력이 있는" 이라는 뜻을 가진 접미사

#### 2) 變數 (변수)
- 변(變): 변화, 바뀌다
- 수(數): 숫자, 셈, 개수

### 5.3.2 변수란?
- 데이터를 담는 그릇
- 변수에 값을 저장한 후 그 값이 필요할 때 변수를 통해서 값을 사용
- 언제든지 그 값을 수정할 수 있음
- 다른 변수와 식별하기 위한 고유의 이름을 가짐

#### 1) 변수 선언
- 데이터를 사용하기 전에 특징에 맞는 데이터형을 미리 지정
- `데이터타입 변수명;` (예: `int age;`)

#### 2) 변수에 값 할당
- 대입연산자(`=`)를 이용하여 값을 저장
- `변수명 = 값;` (예: `age = 25;`)

#### 3) 변수 선언과 동시에 값 할당
- 변수를 선언함과 동시에 초기값을 부여
- `데이터타입 변수명 = 값;` (예: `int score = 100;`)

- 예시:
  ```java
  int age;           // 1. 변수 선언
  age = 25;          // 2. 변수에 값 할당
  age = 26;          // 변수이므로 값 변경 가능

  int score = 100;   // 3. 변수 선언과 동시에 값 할당
  ```

- 예시:
  ```java
  byte b = 100;
  short s = 10000;
  int num = 100000000;
  long bigNum = 3000000000L; // L을 안붙이면 int로 인식해 에러남
  double pi = 3.14159;
  float smallPi = 3.14F;     // F 안붙이면 double로 인식해 에러남
  boolean isGood = true;
  char grade = 'A';

  String name1 = "멋쟁이";
  String name2 = "사자처럼";
  ```

### 5.3.3 상수의 어원
#### 1) constant (상수)
- "con": 라틴어 "com-"에서 유래, '함께', '완전히'라는 의미의 강조 접두사
- "stant": 라틴어 "stare"에서 유래, '서 있다', '머물다'라는 의미
- 즉, "변하지 않고 확고하게 서 있는 상태"를 뜻함

#### 2) 常數 (상수)
- 상(常): 항상, 일정하다
- 수(數): 숫자, 셈, 개수
- 즉, "항상 일정한 수"를 뜻함

### 5.3.4 상수란?
- 한 번 값이 저장되면 프로그램이 실행되는 동안 절대 변경할 수 없는 불변의 데이터 저장소를 가리킴
- 자바에서는 변수 선언부 앞에 `final` 키워드를 붙여 상수를 만듦
- 상수의 이름은 관례적으로 모든 글자를 대문자로 작성하며, 단어와 단어 사이는 언더스코어(`_`)로 구분함
- 상수를 사용하면 값의 의미가 명확해지고 코드의 안정성이 크게 높아짐

- 예시:
  ```java
  final int MAX_SIZE = 100; // 상수 선언 (주로 대문자와 언더스코어 사용)
  // MAX_SIZE = 200; // 에러 발생! 상수는 변경 불가
  ```

### 5.3.5 리터럴(Literal)
- 소스 코드 상에서 프로그래머가 직접 입력한 고정된 값 자체
- 변수나 상수에 할당되는 데이터 값
- 종류:
  - 정수 리터럴: `10`, `0`, `-5`
  - 실수 리터럴: `3.14`, `2.5f`
  - 문자 리터럴: `'A'`, `'가'`
  - 문자열 리터럴: `"Hello"`, `"멋쟁이"`
  - 논리 리터럴: `true`, `false`

- 예시:
  ```java
  int score = 100;          // 100이 정수 리터럴
  final double PI = 3.14;   // 3.14가 실수 리터럴
  ```

## 5.4 식별자와 예약어

### 5.4.1 식별자(Identifier)
- 변수, 상수, 메서드, 클래스 등에 붙여주는 이름
- 개발자가 임의로 지정할 수 있지만 지켜야 할 문법적 규칙과 관례가 있음

#### 1) 식별자 명명 규칙 (문법적 필수)
- 영문 대소문자(유니코드를 지원하므로 한글 등 모든 언어의 문자를 사용할 수 있으나 보통 영문자만 사용), 숫자, 밑줄(`_`), 달러 기호(`$`)만 사용 가능
- 숫자로 시작할 수 없음
- 예약어는 사용할 수 없음
- 길이 제한은 없음

#### 2) 식별자 명명 관례 (개발자 간의 약속)
- 클래스 이름: 대문자로 시작 (PascalCase)
- 변수와 메서드 이름: 소문자로 시작하고 단어가 바뀔 때마다 대문자 사용 (camelCase)
- 상수 이름: 모두 대문자로 작성하며 단어 사이는 밑줄(`_`)로 연결 (SCREAMING_SNAKE_CASE)

### 5.4.2 예약어(Keyword / Reserved Word)
- 자바 언어 문법에서 미리 약속되어 특별한 의미로 사용되는 단어
- 식별자로 사용할 수 없음
- 예: `int`, `class`, `public`, `if`, `for`, `true`, `false` 등

## 5.5 형변환(Type Casting)
서로 다른 타입끼리 연산하거나 대입할 때 크기를 맞춰주는 작업.

#### 1) 자동 형변환 (묵시적 형변환)
- 작은 크기의 타입을 큰 크기의 타입으로 변환할 때 발생 (데이터 손실 없음)
- `byte` -> `short` -> `int` -> `long` -> `float` -> `double`

- 예시:
  ```java
  int a = 10;
  double b = a; // int가 double로 자동 변환. b는 10.0이 됨
  ```

#### 2) 강제 형변환 (명시적 형변환)
- 큰 크기의 타입을 작은 크기의 타입으로 강제 변환할 때 발생 (데이터 손실 위험)
- 괄호 `(타입)`를 명시해야 함

- 예시:
  ```java
  double pi = 3.14;
  int p = (int) pi; // 강제로 소수점을 버림. p는 3이 됨 (데이터 손실)
  ```


# 6. 연산자

## 6.1 산술 연산자
- `+`, `-`, `*`, `/`, `%`(나머지)
- 1+4, 1-4*5, (1+4)*5
- 9/4 -> 2
- 9%4 -> 1
- 결합 연산자(+): 문자열과 함께 사용할 경우 문자열 결합을 의미함
- 예시:
  ```java
  int age = 30;
  String str = "나이는 " + age + " 입니다.";
  System.out.println(str); // 나이는 30 입니다.
  ```
  
## 6.2 대입 연산자
- `=`, `+=`, `-=`, `*=`, `/=`, `%=`
- 우측 항목의 값을 계산한 후 왼쪽 항목에 대입
- 예시:
  ```java
  int a = 10 + 5; //  a = 15
  int sum = 20;
  sum += a; // sum = sum + a 를 의미. sum = 20 + 15
  System.out.println(sum); // 35
  ```

## 6.3 증감 연산자
- `++`, `--`
- 값을 1 증가 또는 감소
- 예시:
  ```java
  int count = 10;
  count++; // count = count + 1 -> 11
  count++; // count = count + 1 -> 12
  count--; // count = count - 1 -> 11
  System.out.println(count); // 11
  ```

- 변수 앞에 붙으면 연산 전 증감(전위 연산), 뒤에 붙으면 연산 후 증감(후위 연산)
- 예시:
  ```java
  int a = 10;
  int b = ++a; // 전위 연산: a의 값을 먼저 1 증가시킨 후 b에 대입함 (a는 11, b는 11이 됨)
  System.out.println("a: " + a + ", b: " + b); // a: 11, b: 11

  int x = 10;
  int y = x++; // 후위 연산: x의 현재 값인 10을 y에 먼저 대입한 후 x를 1 증가시킴 (x는 11, y는 10이 됨)
  System.out.println("x: " + x + ", y: " + y); // x: 11, y: 10
  ```

## 6.4 비교 연산자
- `==`(같다), `!=`(다르다), `>`, `<`, `>=`, `<=`
- 두 항을 비교하여 참이면 true, 거짓이면 false를 반환
- 예시:
  ```java
  System.out.println(1 > 2); // false
  System.out.println(10 <= 10); // true
  System.out.println(100 == 100); // true
  System.out.println(100 != 110); // true
  ```

## 6.5 논리 연산자
### 6.5.1 `&&` (AND)
- 두 항이 모두 참이면 true, 그 외는 false
- 예시:
  ```java
  int age = 19;
  boolean isTeenage = (age >= 10) && (age < 20); // age가 10 이상이고 age가 20 미만일 경우 true, 나머지는 false
  System.out.println(isTeenage); // age가 19이므로 true
  age++;
  isTeenage = (age >= 10) && (age < 20); // age가 10 이상이고 age가 20 미만일 경우 true, 나머지는 false
  System.out.println(isTeenage); // age가 20이므로 false
  ```

### 6.5.2 `||` (OR)
- 두 항 중 하나라도 참이면 true, 그 외는 false
- 예시:
  ```java
  int age = 8;
  boolean isFreeRide = (age <= 8) || (age >= 65); // 8세 이하이거나 65세 이상인 경우 무료 탑승 대상자
  System.out.println(isFreeRide); // age가 8이므로 true
  
  age = 30;
  isFreeRide = (age <= 8) || (age >= 65);
  System.out.println(isFreeRide); // age가 30이므로 false
  ```

### 6.5.3 `!` (NOT)
- 참이면 false, 거짓이면 true (반대값 반환)
- 예시:
  ```java
  boolean isRainy = true;
  boolean isSunny = !isRainy; // 비가 오면 화창하지 않음
  System.out.println("오늘은 화창한 날이다. " + isSunny); // false

  isRainy = false;
  isSunny = !isRainy; // 비가 오지 않으면 화창한 날씨
  System.out.println("오늘은 화창한 날이다. " + isSunny); // true
  ```

## 6.6 삼항 연산자
- `조건식 ? 참일_때_값 : 거짓일_때_값` 단일 조건 제어 흐름에 유용함
- 예시:
  ```java
  int score = 85;
  String result = (score >= 80) ? "합격" : "불합격";
  System.out.println(result); // 합격
  ```

- 실습: ArithmeticOp

## 6.7 연산자 우선순위
- 여러 연산자가 복합적으로 사용된 수식에서 컴파일러가 어떤 연산자를 먼저 계산할지 결정하는 규칙

### 6.7.1 주요 연산자 우선순위 요약 표
수식이 얽혀 있을 때 아래의 순서에 따라 차례대로 연산이 집행됨

| 순위 | 연산자 유형 | 연산자 기호 | 연산 방향 |
| :--- | :--- | :--- | :--- |
| 1 | 괄호 및 대괄호 | (), [] | 왼쪽에서 오른쪽 |
| 2 | 단항 연산자 | ++, --, +, -, ! | 오른쪽에서 왼쪽 |
| 3 | 산술 연산자 (곱셈 계열) | *, /, % | 왼쪽에서 오른쪽 |
| 4 | 산술 연산자 (덧셈 계열) | +, - | 왼쪽에서 오른쪽 |
| 5 | 비교 연산자 (크기 비교) | <, <=, >, >= | 왼쪽에서 오른쪽 |
| 6 | 비교 연산자 (동등 비교) | ==, != | 왼쪽에서 오른쪽 |
| 7 | 논리 연산자 (AND) | && | 왼쪽에서 오른쪽 |
| 8 | 논리 연산자 (OR) | \|\| | 왼쪽에서 오른쪽 |
| 9 | 삼항 연산자 | ? : | 오른쪽에서 왼쪽 |
| 10 | 대입 연산자 | =, +=, -=, *=, /=, %= | 오른쪽에서 왼쪽 |
| 11 | 증감 연산자(후위형) | ++, -- | 2순위에 있지만 편의상 따로 표기 |

### 6.7.2 연산 방향(결합성)의 의미
- 동일한 우선순위를 가진 연산자들이 여러 개 나열되어 있을 때, 컴파일러가 어느 쪽 연산자부터 먼저 해석하여 순서대로 처리해 나갈지 결정하는 방향을 말함

#### 1) 왼쪽에서 오른쪽 (Left-to-Right)
- 대부분의 산술, 비교, 논리 연산이 이에 해당하며 일반적인 계산 순서와 같음
  ```java
  int result = 5 + 3 - 2; // 동일한 우선순위인 덧셈과 뺄셈이 나열됨
  // 처리 순서: (5 + 3) -> 8이 먼저 계산된 후, 8 - 2 가 실행되어 최종 6이 됨
  ```

#### 2) 오른쪽에서 왼쪽 (Right-to-Left)
- 대입 연산자, 단항 연산자 등이 이에 해당하며 우측의 식부터 해석하여 좌측으로 누적 및 대입해 들어옴

- 예시(대입 연산자):
  ```java
  int a;
  int b;
  int c;
  a = b = c = 100; // 우측부터 해석하여 좌측으로 차례대로 저장해 들어옴
  // 처리 순서: 
  // 1. 가장 오른쪽인 (c = 100) 이 실행되어 c에 100이 대입됨
  // 2. 그 후 (b = c의 결과값 100) 이 실행되어 b에 100이 대입됨
  // 3. 마지막으로 (a = b의 결과값 100) 이 실행되어 a에 100이 최종 저장됨
  System.out.println("a: " + a + ", b: " + b + ", c: " + c); // a: 100, b: 100, c: 100
  ```

- 예시(단항 연산자):
  ```java
  int x = 5;
  int y = -++x; // 우측인 ++x를 먼저 수행한 후, 그 결과에 좌측의 부호 연산자(-)를 씌움
  // 처리 순서:
  // 1. 가장 우측에 가까운 ++x가 먼저 계산되어 x가 6이 됨
  // 2. 그 결과값 6에 좌측 부호 연산자(-)가 씌워져 최종 -6이 y에 저장됨
  System.out.println("y: " + y); // -6
  ```

- 예시(삼항 연산자):
  ```java
  int score = 85;
  String grade = (score >= 90) ? "A" : (score >= 80) ? "B" : "C";
  // 삼항 연산자가 연속해서 나열될 때, 우측의 삼항 연산이 먼저 한 그룹으로 결합하고 그 평가 결과가 좌측 연산의 거짓항 요소로 사용됨
  // 처리 순서:
  // 1. 가장 우측의 중첩식인 ((score >= 80) ? "B" : "C") 가 하나의 피연산자 블록으로 먼저 결합함 -> score가 85이므로 결과는 "B"가 됨
  // 2. 이 결과값 "B"가 좌측식의 거짓항 자리에 대입되어 (score >= 90) ? "A" : "B" 가 최종 실행됨
  System.out.println("학점: " + grade); // 학점: B
  ```

### 6.7.3 우선순위 대조 예시
- 예시:
  ```java
  // 1) 곱셈과 덧셈의 우선순위 비교
  int result1 = 5 + 3 * 2; // 곱셈(*)이 덧셈(+)보다 우선하므로 3 * 2가 먼저 수행되어 11이 됨
  System.out.println(result1); // 11

  // 2) 비교 연산과 논리 연산의 우선순위 비교
  boolean result2 = 10 > 5 && 3 < 1; // 비교(>, <)가 논리(&&)보다 우선하여 (true && false)가 되므로 false가 됨
  System.out.println(result2); // false

  // 3) 괄호()를 통한 강제 우선순위 지정 (가장 안전하고 강력한 실무 권장 기법)
  int result3 = (5 + 3) * 2; // 괄호 안의 덧셈이 먼저 실행되어 8 * 2 = 16이 됨
  System.out.println(result3); // 16
  ```

### 6.7.4 실무 가이드 및 권장 사항
- 연산자 우선순위 규칙이 엄격히 존재하지만, 복잡한 수식을 개발자가 전부 암기하여 코드를 작성하면 가독성이 떨어지고 실수할 가능성이 늘어남
- 조금이라도 연산 순서가 모호하거나 수식의 명확성을 높이고자 할 때는 괄호 `()` 로 해당 연산을 감싸서 가독성을 확보하는 것이 좋음

# 7. 조건문

## 7.1 if 문
- 조건식이 참(true)일 때만 지정한 블록을 실행하고, 거짓(false)이면 실행하지 않고 건너뜜
- 형식:
  ```java
  if (조건식) {
    // 조건식이 참일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int score = 95;
  if (score >= 90) {
    System.out.println("우수한 성적입니다."); // score가 95이므로 실행됨
  }

  score -= 10;
  if (score >= 90) {
    System.out.println("우수한 성적입니다."); // score가 85이므로 실행되지 않음
  }
  ```

## 7.2 if-else 문
- 조건식이 참일 경우 if 블록을, 거짓일 경우 else 블록을 실행
- 형식:
  ```java
  if (조건식) {
    // 조건식이 참일 때 실행할 구문
  } else {
    // 조건식이 거짓일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int score = 75;
  if (score >= 60) {
    System.out.println("합격입니다."); // 참일 때 실행
  } else {
    System.out.println("불합격입니다."); // 거짓일 때 실행
  }
  ```

## 7.3 if-else if 문
- 조건식이 참일 경우 해당 구문을 수행하고 거짓일 경우 else if 문의 조건식을 순차적으로 비교하여 참에 해당하는 구문 수행
- 형식:
  ```java
  if (조건식1) {
    // 조건식1이 참일 때 실행할 구문
  } else if (조건식2) {
    // 조건식2가 참일 때 실행할 구문
  } else {
    // 모든 조건식이 거짓일 때 실행할 구문
  }
  ```
- 예시:
  ```java
  int age = 19;
  if (age >= 20) {
    System.out.println("성인");
  } else if (age >= 14) {
    System.out.println("청소년"); // age가 19이므로 이 조건식이 충족되어 실행됨
  } else {
    System.out.println("어린이");
  }

  age += 1;
  if (age >= 20) {
    System.out.println("성인"); // age가 20이므로 이 조건식이 충족되어 실행됨
  } else if (age >= 14) {
    System.out.println("청소년");
  } else {
    System.out.println("어린이");
  }
  ```

- 중괄호 생략 규칙
  + if, else if, else 문 블록 내에 실행할 구문이 단 한 줄(하나의 실행문)일 경우, 중괄호 `{}`를 생략할 수 있음
  + 단, 생략할 경우 코드 가독성이 떨어질 수 있고, 나중에 실행 구문을 추가할 때 버그가 생기기 쉬우므로 실무에서는 가급적 중괄호를 명시적으로 작성하는 것을 권장
  + 예시:
    ```java
    int score = 85;

    // if, else if, else 블록 전체에서 실행문이 한 줄이므로 각각 중괄호 생략 가능
    if (score >= 90)
        System.out.println('우수');
    else if (score >= 80)
        System.out.println('보통'); // score가 85이므로 실행됨
    else
        System.out.println('노력요함');
    ```

## 7.4 switch 문
- switch 구문의 비교값과 같은 case 블록을 찾아서 실행(break 키워드를 만날때까지 아래에 위치한 case 블록을 모두 실행)
- `break` 키워드를 작성하지 않으면 아래에 위치한 다음 `case` 블록들까지 연달아 실행되므로 주의가 필요
- 형식:
  ```java
  switch (비교대상) {
    case 값1:
      // 비교대상이 값1일 때 실행할 구문
      break;
    case 값2:
      // 비교대상이 값2일 때 실행할 구문
      break;
    default:
      // 매칭되는 값이 없을 때 실행할 구문
  }
  ```
- 예시:
  ```java
  String role = "ADMIN";
  switch (role) {
    case "ADMIN":
      System.out.println("관리자 권한"); // role이 "ADMIN"이므로 이곳으로 즉시 점프하여 실행
      break; // switch 문을 즉시 빠져나감
    case "USER":
      System.out.println("일반 사용자");
      // break;
    default:
      System.out.println("권한 없음"); // default는 매칭되는 case가 없을 경우 실행
  }

  role = "USER";
  switch (role) {
    case "ADMIN":
      System.out.println("관리자 권한");
      break;
    case "USER":
      System.out.println("일반 사용자"); // role이 "USER"이므로 이곳으로 즉시 점프하여 실행
      // break;
    default:
      System.out.println("권한 없음"); // default는 매칭되는 case가 없을 경우 실행
  }
  ```

## 7.5 새롭게 추가된 switch 문 (Switch Expression)
- 자바 12 버전부터 도입(자바 14 정식 표준화)된 새로운 형태의 switch 문
- 기존의 콜론(:)과 break 키워드를 사용하는 방식 대신 화살표 연산자(->)를 활용하여 가독성을 높이고 실수를 방지
- 기존 switch 문이 실행만을 목적으로 하는 제어문(Statement)이었다면, 새로운 switch 문은 그 자체로 최종 결과를 직접 반환할 수 있는 식(Expression)으로 동작 가능
- 주요 특징:
  + break 키워드 불필요: case에 해당하는 명령문만 실행하고 자동으로 switch 문을 빠져나감
  + 다중 조건 결합: 쉼표(,)를 사용하여 여러 case 조건을 한 줄에 간결하게 묶어 선언할 수 있음
  + 값의 직접 반환: switch 식 자체를 변수의 대입 연산 우측에 배치하여 값을 직접 반환받을 수 있음
  + yield 키워드: 복잡한 명령 처리를 위해 중괄호 { } 블록을 구성할 경우, 블록 내부에서 yield 키워드를 사용하여 최종 결과값을 외부로 반환할 수 있음

- 예시(화살표 연산자):
  ```java
  String role = "ADMIN";
  switch (role) {
      case "ADMIN" -> System.out.println("관리자 권한");
      case "USER" -> System.out.println("일반 사용자");
      default -> System.out.println("권한 없음");
  }
  ```

- 예시(다중 조건 결합):
  ```java
  String day = "SATURDAY";
  String type = switch (day) {
      case "MONDAY", "TUESDAY", "WEDNESDAY", "THURSDAY", "FRIDAY" -> "평일";
      case "SATURDAY", "SUNDAY" -> "주말";
      default -> "알 수 없음";
  };
  System.out.println(type); // '주말' 출력
  ```

- 예시(switch 식 대입):
  ```java
  int number = 2;
  String result = switch (number) {
      case 1 -> "하나";
      case 2 -> "둘";
      default -> "기타";
  };
  System.out.println(result); // '둘' 출력
  ```

- 예시(블록과 yield 키워드 사용):
  ```java
  int score = 90;
  String grade = switch (score) {
      case 100, 90 -> {
          System.out.println("우수한 성적입니다.");
          yield "A"; // 중괄호 블록 내의 최종 반환값 지정
      }
      case 80 -> "B";
      default -> "C";
  };
  System.out.println("최종 학점: " + grade); // '최종 학점: A' 출력
  ```

# 8. 반복문
## 8.1 while 문
- 지정한 조건식이 참일 경우 조건이 거짓이 될 때까지 해당 블록을 반복하여 수행
- 주로 반복 횟수는 정해져 있지 않지만 특정 조건이 만족할 때까지 루프를 유지할 때 사용함
- 형식:
  ```java
  while (조건식) {
    // 조건식이 참인 동안 반복해서 실행할 구문
  }
  ```
- 예시:
  ```java
  int i = 0;
  while (i < 3) {
    System.out.println("while 루프: " + i);
    i++; 
  }
  ```

## 8.2 do-while 문
- 일단 블록의 내부 구문을 최초 1회 무조건 먼저 실행한 후, 조건식을 사후 검사하여 조건이 참인 동안 루프를 지속하는 제어문
- 조건식의 만족 여부에 상관없이 최소 1번의 실행을 보장해야 할 때 주로 사용
- 형식:
  ```java
  do {
    // 최소 1회 무조건 실행 및 조건식이 참인 동안 반복해서 실행할 구문
  } while (조건식);
  ```
- 예시:
  ```java
  int j = 10;
  do {
    System.out.println("do-while 무조건 한번은 실행됨: " + j);
  } while (j < 5); // 거짓이지만 위에서 이미 한번 출력됨
  ```

## 8.3 for 문
- 지정한 조건식이 참일 경우 조건이 거짓이 될 때까지 해당 블록을 반복하여 수행
- 반복 횟수가 명확할 때 주로 사용
- 형식:
  ```java
  for (초기화; 조건식; 증감식) {
    // 조건식이 참인 동안 반복해서 실행할 구문
  }
  ```
- 실행 순서
  + 초기화 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + 증감식 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + 증감식 -> 조건식 -> (조건식이 true일 경우) 실행할 구문
  + ... 조건식이 false가 될 때까지 실행
- 예시:
  ```java
  for (int i = 0; i < 5; i++) {
    System.out.println("현재 숫자: " + i); // 0부터 4까지 5번 출력
  }
  ```

- 실습: ForTest
- 실습: ForTest2

## 8.4 break와 continue
- `break`: 실행되는 순간 소속된 switch문이나 반복문을 종료하고 탈출
- `continue`: 이번 턴만 건너뛰고 다음 턴으로 바로 넘어감

- 예시:
  ```java
  // 1) break: i가 3일 때 반복문을 완전히 종료하고 탈출함
  for (int i = 1; i <= 5; i++) {
      if (i == 3) {
          break; 
      }
      System.out.println("break 출력: " + i); // 1, 2 출력
  }

  // 2) continue: i가 3일 때 이번 출력 턴만 건너뛰고 4로 넘어감
  for (int i = 1; i <= 5; i++) {
      if (i == 3) {
          continue; 
      }
      System.out.println("continue 출력: " + i); // 1, 2, 4, 5 출력
  }
  ```

# 9. 배열과 메모리 관리

## 9.1 배열의 개념과 선언
- 배열이란 같은 타입의 데이터 여러 개를 하나로 묶어서 관리하는 바구니
- 정적 할당: 자바의 배열은 처음에 크기를 정하면 나중에 절대 늘리거나 줄일 수 없음
- 배열 자체는 객체이므로 JVM 힙 영역에 생성되며 `new` 연산자를 사용해야 함

- 예시:
  ```java
  // 선언과 동시에 5칸짜리 빈 배열 생성 (정수 기본값 0으로 채워짐)
  int[] scores = new int[5]; 

  // 값 넣기 (인덱스는 0부터 시작!)
  scores[0] = 100;
  scores[1] = 90;

  // 선언과 동시에 데이터 채워넣기 (초기화)
  String[] names = {"김사자", "이멋쟁", "박백엔드"};
  ```

- 실습: ArrayTest

## 9.2 다차원 배열
- 2차원 이상의 배열을 의미하며 행렬 구조와 비슷
- 자바에서는 배열의 배열 개념으로 처리됨

- 예시:
  ```java
  int[][] matrix = new int[2][3]; // 2행 3열 배열
  matrix[0][0] = 1;
  matrix[1][2] = 5;

  // 초기화와 동시에 생성
  int[][] arr = {

  };
  ```

## 9.3 향상된 for문

## 9.4 배열의 복사와 Arrays 클래스

- `System.arraycopy()`나 `Arrays.copyOf()`를 활용

- 예시:
  ```java
  import java.util.Arrays;
  ```

# 10. 모듈화와 메서드(Method)

## 10.1 메서드 선언과 반환 타입
- 특정 기능(코드 블록)을 하나로 묶어놓은 것
- 중복되는 코드를 복붙하지 않고, 메서드로 만들어두면 재사용 가능

- 예시:
  ```java
  // 접근제어자 반환타입 메서드명(매개변수)
  public int add(int a, int b) {
      int sum = a + b;
      return sum; // 결과값 반환
  }
  ```
- 반환할 게 없으면 반환타입에 `void`를 씀

## 10.2 메서드 오버로딩 (Overloading)
- 한 클래스 안에서 메서드 이름은 똑같이 하되, 매개변수(개수나 타입)를 다르게 여러 개 만드는 것
- 사용자의 편의성을 극대화함

- 예시:
  ```java
  public int multiply(int a, int b) { return a * b; }
  public double multiply(double a, double b) { return a * b; }
  public int multiply(int a, int b, int c) { return a * b * c; }
  ```

## 10.3 가변 인자(varargs)
- 매개변수의 개수를 동적으로 지정할 수 있는 기능
- 내부적으로는 배열로 처리됨
- 가변 인자는 매개변수 목록의 가장 마지막에만 위치할 수 있음

- 예시:
  ```java
  public void printNumbers(int... nums) {
      for (int num : nums) {
          System.out.println(num);
      }
  }
  // 호출: printNumbers(1, 2, 3);
  // 호출: printNumbers(10, 20);
  ```

# 11. 객체지향 프로그래밍(OOP) 기초

## 11.1 클래스와 객체(인스턴스)
- 클래스(Class): 붕어빵 틀. 객체를 만들기 위한 설계도이며 메모리에 실체는 없음
- 인스턴스(Instance): 붕어빵. 설계도를 바탕으로 `new` 연산자를 통해 힙 메모리에 구워져 나온 실제 결과물(객체)

## 11.2 클래스의 구성 요소
1. 필드 (Field): 객체의 상태, 속성 (변수)
2. 메서드 (Method): 객체의 동작, 행위 (함수)
3. 생성자 (Constructor): 객체가 `new`로 생성될 때 초기 세팅을 담당

- 예시:
  ```java
  public class Car {
      String model;
      int speed;

      // 생성자 (반환 타입 없음)
      public Car(String model) {
          this.model = model;
          this.speed = 0;
      }

      public void accelerate() {
          this.speed += 10;
          System.out.println(model + " 속도 증가! 현재 속도: " + speed);
      }
  }
  ```

## 11.3 생성자 (Constructor)
- 객체가 new 연산자를 통해 메모리에 생성될 때 가장 먼저 호출되어 인스턴스 변수의 초기 세팅을 담당하는 특수한 메서드임
- 주요 특징:
  + 반환 타입이 없음: 일반 메서드와 달리 void조차 지정하지 않으며, 이름은 반드시 소속 클래스명과 대소문자까지 일치해야 함
  + 기본 생성자 (Default Constructor): 클래스 내부에 개발자가 생성자를 단 하나도 선언하지 않으면 컴파일러가 매개변수와 코드가 없는 빈 기본 생성자를 자동으로 삽입해 줌. 단, 매개변수가 있는 생성자를 하나라도 정의하면 기본 생성자는 자동으로 생성되지 않으므로 필요시 직접 명시해야 함
  + 생성자 오버로딩: 매개변수의 개수와 타입을 다르게 하여 하나의 클래스 내부에 생성자를 여러 개 조립하여 다형성을 제공할 수 있음

- 예시(생성자 오버로딩):
  ```java
  public class Book {
      String title;
      String author;

      // 기본 생성자 (개발자가 명시적으로 정의)
      public Book() {
          this.title = "제목없음";
          this.author = "작자미상";
      }

      // 매개변수가 있는 생성자 (오버로딩)
      public Book(String title, String author) {
          this.title = title;
          this.author = author;
      }
  }
  ```

## 11.4 this와 this()
- `this`: 생성된 자기 자신 객체를 가리키는 참조 변수. 매개변수와 필드명이 같을 때 구별하기 위해 사용
- `this()`: 같은 클래스 내의 다른 생성자를 호출할 때 사용. 생성자 내부의 첫 줄에만 작성 가능

- 예시:
  ```java
  public class User {
      String name;
      int age;

      public User() {
          this("기본이름", 1); // 다른 생성자 호출
      }

      public User(String name, int age) {
          this.name = name;
          this.age = age;
      }
  }
  ```

## 11.5 패키지와 임포트
- 패키지: 관련된 클래스들을 그룹화하는 폴더 구조
- 임포트(`import`): 다른 패키지에 있는 클래스를 사용할 때 명시

## 11.6 캡슐화와 접근 제어자
- 캡슐화: 중요한 데이터를 외부에서 임의로 변경하지 못하도록 은닉하는 기법
- 접근 제어자: `private` < `default` < `protected` < `public`
- 필드를 `private`으로 선언하고 Getter/Setter 메서드를 통해 접근을 제어

- 예시:
  ```java
  public class Account {
      private int balance; // 외부 접근 차단

      public int getBalance() {
          return this.balance;
      }

      public void deposit(int amount) {
          if (amount > 0) {
              this.balance += amount;
          }
      }
  }
  ```

## 11.7 정적(static) 멤버
- `static` 키워드가 붙은 필드나 메서드는 인스턴스 생성을 하지 않아도 클래스명으로 바로 접근 가능
- 모든 인스턴스가 공유하는 메모리(메서드 영역)에 저장됨

- 예시:
  ```java
  public class MathUtils {
      public static final double PI = 3.14159;
      
      public static int add(int a, int b) {
          return a + b;
      }
  }
  // 호출: MathUtils.add(10, 20);
  ```

## 11.8 문자열 클래스 (String, StringBuffer, StringBuilder)

### 11.8.1 String 클래스의 내부 메커니즘과 불변성 (Immutability)
String 객체는 한 번 생성되면 메모리 상에서 그 내부 값을 절대로 변경할 수 없는 불변(Immutable) 객체임

#### 1) 문자열 상수 풀 (String Constant Pool)
- 자바는 메모리 효율성과 안정성을 높이기 위해 힙 메모리 영역 내부에 '문자열 상수 풀'이라는 특수한 공유 메모리를 구성함
- 문자열을 리터럴(예: 'Hello')로 선언할 경우, JVM은 먼저 이 상수 풀에 동일한 문자열이 있는지 찾아보고 있으면 새로운 객체를 생성하지 않고 기존 객체의 주소값을 공유하여 참조함
- 이로 인해 문자열 값의 비교 시 주소 비교(==)가 아닌 내용 비교(equals)를 지향해야 함

#### 2) 문자열 결합 연산의 부작용
- String 객체에 결합 연산자(+)를 사용하여 문자열을 더하면 기존 객체의 내용이 바뀌는 것이 아니라, 결합된 새로운 문자열 객체가 상수 풀에 생성되고 참조 변수는 그 새 객체의 주소를 가리킴
- 따라서 루프 안에서 문자열을 덧붙이는 연산을 무수히 수행하면 힙 영역에 무수히 많은 임시 찌꺼기 객체들이 쌓여 가비지 컬렉터(GC)의 성능 하락을 초래하게 됨

### 11.8.2 가변 문자열 클래스: StringBuffer와 StringBuilder
- 문자열의 잦은 추가, 삽입, 삭제가 일어나는 프로그램에서는 힙 공간의 낭비를 방지하기 위해 가변(Mutable) 객체 클래스를 채택해야 함
- 이들은 내부에 가변적인 크기의 메모리 버퍼를 탑재하여 객체를 새로 복사하지 않고 즉석에서 문자열을 편집할 수 있음

#### 1) StringBuffer
- 멀티스레드 환경에 매우 안전하도록 동기화(Thread-safe) 처리가 설계되어 있음
- 여러 실행 흐름이 동시에 하나의 문자열에 접근하더라도 데이터 꼬임 현상이 완벽히 방지됨

#### 2) StringBuilder
- 동기화 처리가 빠진 대신 싱글스레드 환경에서 StringBuffer에 비해 훨씬 뛰어난 동작 속도와 효율성을 보여줌
- 일반적인 웹 백엔드 로컬 변수의 조작 과정에서는 속도 최적화를 위해 StringBuilder를 우선적으로 사용하는 것이 관례임

### 11.8.3 String 주요 메서드
- length(): 문자열의 총 길이를 숫자로 반환함
- charAt(int index): 지정된 인덱스 위치에 있는 하나의 문자를 반환함
- substring(int begin, int end): 시작 인덱스부터 끝 인덱스 직전까지의 문자열을 잘라내어 반환함
- equals(Object obj): 대상 객체와 내용이 같은지 논리 여부(true/false)를 반환함
- indexOf(String str): 찾고자 하는 문자열이 처음 시작하는 인덱스를 반환하며, 존재하지 않으면 -1을 반환함
- replace(CharSequence target, CharSequence replacement): 특정 텍스트를 대상 텍스트로 전부 치환한 새 문자열을 반환함
- split(String regex): 지정된 구분 기호를 기준으로 쪼갠 후 문자열 배열(String[])로 최종 반환함

### 11.8.4 StringBuffer 주요 메서드
- append(String str): 기존 버퍼의 끝 부분에 인자로 주어진 문자열을 즉석에서 추가함
- insert(int offset, String str): 특정 오프셋 위치에 인자로 주어진 문자열을 즉석에서 삽입함
- delete(int start, int end): 특정 시작 범위부터 끝 범위 직전까지의 문자를 안전하게 제거함
- reverse(): 저장되어 있는 문자열을 가로축 기준 좌우로 완전히 뒤집음
- toString(): 버퍼 내의 가변 조작 연산이 끝난 후 최종적으로 String 객체 타입으로 환원하여 안전하게 반환함

### 11.9 자바 API 문서
자바 API 문서(Java API Specification)는 자바가 표준으로 설계하여 탑재해 둔 수천 개의 클래스와 인터페이스, 메서드들의 상세 명세서(사용 가이드, 파라미터, 반환 규격)를 정리한 공식 온라인 문서

#### 1) 공식 API 문서 확인
- 오라클 공식 자바 표준 문서 저장소: https://docs.oracle.com/en/java/javase/
- 현재 학습 중인 JDK 버전을 선택한 후 API 문서 확인

#### 2) 공식 문서를 통한 String 클래스 분석
- 클래스 기본 명세 확인: java.lang.String 클래스가 최상위 클래스인 Object로부터 어떻게 파생되었는지 상속 계층도(Hierarchy) 확인
- 구현하는 인터페이스 확인: String 클래스가 Comparable 이나 Serializable 같은 표준 인터페이스들을 구현함을 확인
- Constructor Summary (생성자 요약): 다양한 매개변수를 받는 여러 생성자들의 리스트와 그에 따른 오버로딩 설계 확인
- Method Summary (메서드 요약):
  + Modifier and Type: 해당 메서드가 static으로 전역 공유되는 메서드인지, 혹은 일반 인스턴스 메서드인지와 리턴되는 타입(int, boolean, String 등)을 확인
  + Method and Description: 메서드명과 매개변수를 매핑하여, 어떠한 기능을 수행하고 예외 상황 시 어떤 동작을 하는지 확인
  + Throws: 메서드 사용 중 파라미터 유효성에 문제가 생길 때(예: NullPointerException) 어떤 내부 예외를 개발자에게 호출하여 던져주는지 확인

#### 3) 통합 개발 환경(IDE) 내에서의 API 툴팁 단축키 활용
- IntelliJ에서 웹 브라우저를 직접 띄우지 않고도, 소스코드 내 클래스명이나 메서드명 위에 마우스를 올리면 공식 자바 API 문서 설명이 팝업으로 노출됨
- 단축키: Ctrl + Q (Windows) 또는 F1 (Mac) 키를 누르면, API 주석 설명문을 새로운 탭으로 확인 가능
