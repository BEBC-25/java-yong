# 11. 객체지향 프로그래밍(OOP) 기초

객체지향 프로그래밍(Object-Oriented Programming, OOP)은 컴퓨터 프로그램을 단순한 명령어의 나열로 보지 않고, 독립된 단위인 객체들이 모여서 서로 메시지를 주고받으며 협력하는 형태로 작성하는 프로그래밍 패러다임

- 핵심 지향점:
  + 프로그램의 부품화: 데이터와 이를 처리하는 메서드를 객체라는 하나의 부품으로 결합하여 구조화함
  + 재사용성과 유지보수성: 완성도 높은 객체를 만들어 여러 곳에서 다시 사용하며, 변경 사항이 생겼을 때 해당 객체만 수정하여 부작용을 최소화함

## 11.1 객체, 클래스, 인스턴스
- 객체(Object): 우리가 인지하고 표현하려는 유무형의 모든 실체(예: 자동차, 사람, 은행 계좌 등). 고유한 속성(상태)과 행위(동작)를 가짐
  + 일상생활 속 객체의 예시:
    - 자동차:
      + 속성(필드): 모델명, 색상, 현재 속도
      + 기능(메서드): 출발하기, 가속하기, 브레이크 밟기
    - 은행 계좌:
      + 속성(필드): 계좌번호, 예금주, 잔액
      + 기능(메서드): 입금하기, 출금하기, 잔액조회
- 클래스(Class): 객체를 생성하기 위한 설계도(틀). 객체의 형태와 기능(속성과 행위)을 자바 코드로 사전에 명세해 둔 규격
- 인스턴스(Instance): 클래스라는 설계도를 바탕으로 'new' 연산자를 사용하여 힙 메모리에 실제로 만들어진 실체화된 결과물(객체)

- 💻 실습 (학사 관리 시스템 클래스 설계): [ch11/lms](../workspace/ch11/lms)

## 11.2 클래스의 구성 요소
1. 필드 (Field): 객체의 상태, 속성을 정의한 변수
2. 메서드 (Method): 객체의 동작, 행위, 기능을 담고 있는 코드 블럭
3. 생성자 (Constructor): 객체가 new로 생성될 때 초기 세팅을 담당

- 형식:
  ```java
  [접근제어자] class 클래스명 {
    // 1. 필드 (객체의 상태, 속성 변수)
    [접근제어자] 타입 필드명;

    // 2. 생성자 (객체의 초기 세팅 담당)
    [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
      // 초기 세팅 코드
      // ...
    }

    // 3. 메서드 (객체의 동작, 행위 함수)
    [접근제어자] 반환타입 메서드명(매개변수타입 매개변수명, ...) {
      // 실행할 코드
      // ...
      return 반환값;
    }
  }
  ```

- 예시:
  ```java
  public class Car {
    // 필드
    String model;
    int speed;

    // 생성자
    public Car(String model) {
      this.model = model;
      this.speed = 0;
    }

    // 메서드
    public void accelerate() {
      this.speed += 10;
      System.out.println(model + " 속도 증가! 현재 속도: " + speed);
    }
  }
  ```

## 11.3 필드 (Field)
필드(Field)는 클래스 내부(메서드 외부)에 선언되어 객체의 상태와 속성을 정의하는 변수로, 멤버 변수라고도 부름.

### 11.3.1 필드의 주요 특징
- 자동 초기화: 필드는 명시적으로 초기화하지 않아도 객체가 생성될 때 각 자료형의 기본값으로 자동 초기화 됨.
- 기본값 목록:
  + 정수형 (byte, short, int, long): 0
  + 실수형 (float, double): 0.0
  + 논리형 (boolean): false
  + 문자형 (char): '\u0000' (공백 문자)
  + 참조형 (String, 배열, 클래스 등): null

### 11.3.2 필드 선언 예시
```java
public class Product {
  // 필드 선언 (기본값으로 자동 초기화됨)
  String name;       // null로 초기화
  int price;         // 0으로 초기화
  boolean isSoldOut; // false로 초기화
}
```

## 11.4 객체의 생성과 사용 방법
클래스를 설계도로 삼아 실제 메모리에 실체(객체/인스턴스[^1])를 올리려면 `new` 연산자를 사용해야 하며, 생성된 객체의 멤버(필드와 메서드)에 접근하기 위해서는 닷(`.`) 연산자를 활용함.

### 11.4.1 new 연산자를 통한 인스턴스화 과정
- `new` 연산자는 JVM에게 객체를 저장할 메모리 공간을 힙(Heap) 영역에 할당하도록 요청.
- 메모리 할당이 완료되면 클래스에 정의된 필드들이 힙 공간에 생성되고, 생성자를 호출하여 초기 설정을 완료.
- 마지막으로 생성된 객체가 위치한 힙 영역의 참조 주소값(Reference)을 반환하여 변수에 대입할 수 있도록 함.

### 11.4.2 닷(.) 연산자를 통한 속성 및 기능 제어
- 대입받은 참조 변수 이름 뒤에 닷(`.`)을 붙여서 객체 내부의 변수(필드) 값을 읽거나 수정하고, 함수(메서드)를 호출하여 특정 동작을 수행시킴.

```java
// 클래스 설계도
class Person {
  String name;
  int age;

  void introduce() {
    System.out.println("제 이름은 " + name + "이고, 나이는 " + age + "세입니다.");
  }
}

public class ObjectUsageTest {
  public static void main(String[] args) {
    // 1. new 연산자를 이용한 객체 생성 및 참조 주소 보관
    Person person = new Person();

    // 2. 닷(.) 연산자를 통해 필드에 값 대입
    person.name = "하루";
    person.age = 6;

    // 3. 닷(.) 연산자를 통해 인스턴스 메서드 호출
    person.introduce(); // 출력: 제 이름은 하루이고, 나이는 6세입니다.
  }
}
```

## 11.5 생성자 (Constructor)
- 객체가 new 연산자를 통해 메모리에 생성될 때 가장 먼저 호출되어 인스턴스[^1] 변수의 초기 세팅을 담당하는 특수한 메서드

- 형식:
  ```java
  [접근제어자] 클래스명(매개변수타입 매개변수명, ...) {
    // 인스턴스 변수 초기화 코드
  }
  ```

- 주요 특징:
  + 반환 타입이 없음: 일반 메서드와 달리 void조차 지정하지 않으며, 이름은 반드시 소속 클래스명과 대소문자까지 일치해야 함
  + 기본 생성자 (Default Constructor): 클래스 내부에 개발자가 생성자를 단 하나도 선언하지 않으면 컴파일러가 매개변수와 코드가 없는 빈 기본 생성자를 자동으로 삽입해 줌. 단, 매개변수가 있는 생성자를 하나라도 정의하면 기본 생성자는 자동으로 생성되지 않으므로 필요시 직접 명시해야 함

```java
public class Member {
  String id;

  // 생성자 정의: 반환 타입이 없으며 클래스명과 동일해야 함
  public Member(String id) {
    this.id = id; // 인스턴스 필드 초기화
  }

  public static void main(String[] args) {
    // 객체 생성 시 생성자에 인수 전달
    Member member = new Member("user1");
    System.out.println("회원 아이디: " + member.id); // 출력: 회원 아이디: user1
  }
}
```

## 11.6 생성자 오버로딩
- 매개변수의 개수와 타입을 다르게 하여 하나의 클래스 내부에 생성자를 여러 개 조립하여 다형성[^2]을 제공할 수 있음

- 예시:
  ```java
  public class Book {
    String title;
    String author;

    // 기본 생성자 (개발자가 명시적으로 정의)
    public Book() {
      this.title = "제목없음";
      this.author = "작자미상";
    }

    // 매개변수가 있는 생성자 (오버로딩)
    public Book(String title, String author) {
      this.title = title;
      this.author = author;
    }
  }

  public class BookTest {

      // 매개변수가 있는 생성자 호출
      Book book2 = new Book("자바를 잡아라", "용쌤");
      // book2 제목: 자바를 잡아라, 저자: 용쌤
  ```

## 11.7 this와 this()
- this: 생성된 자기 자신 객체를 가리키는 참조 변수. 매개변수와 필드명이 같을 때 구별하기 위해 사용
- this(): 같은 클래스 내의 다른 생성자를 호출할 때 사용. 생성자 내부의 첫 줄에만 작성 가능
  + Java 25 부터는 생성자의 어느곳에 위치해 있어도 상관없음. 단, 인스턴스[^1] 생성 후에 만 사용 가능한 this나 인스턴스[^1] 메서드의 호출보다는 먼저 작성해야 함.

- 예시:
  ```java

      System.out.println("user2 이름: " + user2.name + ", 나이: " + user2.age);
    }
  }
  ```

## 11.9 캡슐화와 접근 제어자
- 캡슐화: 중요한 데이터와 이를 처리하는 메서드를 하나로 묶고, 외부에서 임의로 변경하지 못하도록 데이터를 은닉하는 기법
- 접근 제어자: private < default < protected < public 순서로 접근 권한을 제한함(오른쪽으로 갈수록 접근 범위가 넓음)
- 필드를 private으로 선언하고 Getter/Setter 및 유효성 검증 메서드를 통해서만 접근하도록 제한함
  + 잔고 확인 없는 출금의 문제점: 필드에 직접 접근할 수 있거나 검증이 없다면, 현재 잔액보다 많은 금액을 출금하여 계좌 잔고가 음수(마이너스)가 되는 금융 사고가 발생할 수 있음. 캡슐화를 통해 잔고 확인 등의 검증 로직을 거쳐서만 출금하도록 제어함

### 11.9.1 접근 제어자별 세부 접근 범위
클래스, 필드, 메서드, 생성자의 사용 허용 범위를 결정하는 접근 제어자의 세부 허용 한계는 다음과 같음.

| 접근 제어자 | 클래스 내부 | 동일 패키지 | 동일 패키지 또는 자식 클래스 | 어디서나 |
| :--- | :--- | :--- | :--- | :--- |
| public | 허용 (O) | 허용 (O) | 허용 (O) | 허용 (O) |
| protected | 허용 (O) | 허용 (O) | 허용 (O) | 차단 (X) |
| default | 허용 (O) | 허용 (O) | 차단 (X) | 차단 (X) |
| private | 허용 (O) | 차단 (X) | 차단 (X) | 차단 (X) |

- public: 어떠한 제한 없이 모든 곳에서 접근이 가능함
- protected: 동일한 패키지 내의 클래스 및 다른 패키지에 있더라도 해당 클래스를 상속[^3]받은 자식 클래스에서 접근이 가능함
- default (package-private): 제어자를 생략했을 때 자동으로 부여되며, 동일 패키지 내부에서만 접근을 허용함
- private: 오직 선언된 해당 클래스 내부에서만 호출 및 접근이 가능함

### 11.9.2 Getter와 Setter 작성 규칙 (네이밍 관례)
클래스 외부에서 private 필드에 안전하게 접근하고 값을 변경하기 위해 사용하는 Getter와 Setter 메서드는 다음과 같은 네이밍 규칙을 따름.

- 일반적인 필드 네이밍 규칙:
  + Getter: get + 필드명 (첫 글자 대문자) (예: String name -> getName())
  + Setter: set + 필드명 (첫 글자 대문자) (예: setName(String name))
- 논리형 (boolean) 필드 예외 규칙:
  + 논리형 필드의 Getter는 get 대신 is로 시작하는 것이 관례이며, Setter는 다른 자료형과 동일하게 set으로 시작함
    - 예시: boolean isSoldOut -> Getter: isSoldOut(), Setter: setSoldOut(boolean isSoldOut)

- 예시 1: 캡슐화가 적용되지 않아 데이터 무결성이 깨지는 문제 예시
  ```java
  public class AccountBad {
    public int balance; // 외부 직접 접근 허용

    public void deposit(int amount) {
      if (amount > 0) {
        this.balance += amount;
      }
    }

    // 출금 메서드: 잔고 확인 로직을 구현하여 마이너스 잔고 문제를 예방
    public void withdraw(int amount) {
      if (amount > 0 && this.balance >= amount) {
        this.balance -= amount;
      } else {
        System.out.println("출금 실패: 잔액 부족 또는 부적절한 금액");
      }
    }
  }

  public class AccountBadTest {
    public static void main(String[] args) {
      AccountBad account = new AccountBad();

      account.deposit(10000); // 10000원 입금
      account.withdraw(15000); // 출력: 출금 실패: 잔액 부족 또는 부적절한 금액

      // 제약 조건 없이 필드에 직접 음수 대입이 가능하여 데이터 오염 발생
      account.balance = -5000;
      System.out.println("계좌 잔고: " + account.balance); // 출력: 계좌 잔고: -5000
    }
  }
  ```

- 예시 2: 캡슐화를 적용하여 데이터를 안전하게 보호하는 해결 예시
  ```java
  public class Account {
    private int balance; // 외부 접근 차단 (음수 잔고 예방)

  public class AccountTest {

      // account.balance = -5000; // 컴파일 에러 발생 (접근이 차단됨)
  ```

## 11.10 정적(static) 멤버
- static 키워드가 붙은 필드나 메서드는 인스턴스[^1] 생성을 하지 않아도 클래스명으로 바로 접근 가능
- 모든 인스턴스[^1]가 공유하는 메모리(메서드 영역)에 저장됨
- static 메서드의 제한 사항:
  + static 메서드는 객체 생성 전 클래스 로딩 시점에 메모리에 올라가므로, 메모리에 존재 여부가 불확실한 인스턴스[^1] 필드나 인스턴스[^1] 메서드에 직접 접근할 수 없음
  + static 메서드 내부에서는 오직 static 필드(클래스 변수)나 static 메서드만 직접 호출이 가능함
  + 객체 자신을 가리키는 참조 키워드인 this는 static 메서드 내부에서 사용할 수 없음
  + 대표적인 static 메서드인 main 메서드 내부에서 동일 클래스의 다른 일반 메서드를 직접 호출하려고 하면 컴파일 에러가 발생함. 이를 호출하려면 대상 메서드가 static이거나, main 메서드 내에서 자기 자신의 객체를 new로 생성하여 접근해야 함


- 예시 1: 정적 멤버 기본 활용
  ```java
  public class MathUtils {
    public static final double PI = 3.14159;

    public static int add(int a, int b) {
      return a + b;
    }
  }
  // 호출: MathUtils.add(10, 20);
  ```

- 예시 2: static 메서드 내에서의 접근 제한
  ```java
  public class Calculator {
    int instanceVal = 10;      // 인스턴스 변수
    static int staticVal = 20; // 클래스(static) 변수

    public static void staticMethod() {
      System.out.println(staticVal); // OK: static 변수 접근 가능
      // System.out.println(instanceVal); // 컴파일 에러: 인스턴스 변수에 직접 접근 불가
    }

    public void instanceMethod() {
      System.out.println(staticVal);   // OK: 인스턴스 메서드에서는 static 변수 접근 가능
      System.out.println(instanceVal); // OK: 인스턴스 변수 접근 가능
    }
  }
  ```

- 예시 3: main 메서드에서의 호출 제한과 해결 방안
  ```java
  public class MainMethodTest {
    public void instanceShow() {
      System.out.println("인스턴스 메서드 호출");
    }

    public static void staticShow() {
      System.out.println("정적 메서드 호출");
    }

    public static void main(String[] args) {
      // static 메서드는 직접 호출이 가능함
      staticShow(); // OK

      // 인스턴스 메서드는 직접 호출 불가능 (컴파일 에러 발생)
      // instanceShow(); // 컴파일 에러: static 영역에서 non-static 메서드 직접 참조 불가

      // 자신의 인스턴스를 직접 생성한 후에 참조 변수를 통해서만 접근할 수 있음
      MainMethodTest test = new MainMethodTest();
      test.instanceShow(); // OK
    }
  }
  ```

## 11.11 변수의 종류와 비교 (지역 변수, 인스턴스 변수, 클래스 변수)
자바 프로그래밍에서 변수는 선언 위치와 static 키워드 사용 여부에 따라 크게 세 가지 종류로 구분되며, 각각 메모리 저장 영역, 생명 주기, 초기화 방식에 차이가 있음.

| 구분 | 지역 변수 (Local Variable) | 인스턴스[^1] 변수 (Instance Variable / 필드) | 클래스 변수 (Class Variable / 정적 필드) |
| :--- | :--- | :--- | :--- |
| 선언 위치 | 메서드, 생성자, 블록 내부 | 클래스 블록 내부 (static 없음) | 클래스 블록 내부 (static 있음) |
| 저장 영역 | 스택 (Stack) 영역 | 힙 (Heap) 영역 | 메서드 (Method / Static) 영역 |
| 초기화 방식 | 자동 초기화 안 됨 (사용 전 초기화 필수) | 기본값으로 자동 초기화 | 기본값으로 자동 초기화 |
| 생성 시점 | 변수 선언문이 실행될 때 | 객체(인스턴스)가 생성될 때 | 클래스가 메모리에 로드될 때 |
| 소멸 시점 | 선언된 블록이 종료될 때 | 객체가 GC에 의해 소멸할 때 | 프로그램이 종료될 때 |

### 11.11.1 메모리 저장 영역과 생명 주기의 차이
- 지역 변수: 메서드가 호출될 때 JVM 스택 영역의 스택 프레임 내부에 생성됨. 메서드 실행이 완료되면 해당 스택 프레임이 제거되면서 지역 변수도 메모리에서 즉시 소멸됨.
- 인스턴스[^1] 변수(필드): 객체가 new 연산자로 생성될 때 JVM 힙 영역에 생성됨. 객체가 더 이상 참조되지 않아 가비지 컬렉터(GC)에 의해 수거되어 소멸할 때까지 힙 메모리에 유지됨.
- 클래스 변수(정적 필드): 프로그램 실행 시 해당 클래스가 메모리에 로드될 때 JVM 메서드 영역에 단 한 번 생성됨. 프로그램 전체에서 공유되며, 프로그램이 종료될 때까지 메모리에 유지됨.

```java
public class VariableScope {
  // 인스턴스 변수: 힙 영역에 생성되며, 인스턴스마다 독립된 값을 보유
  int instanceVar;

  // 클래스 변수: 메서드 영역에 생성되며, 모든 인스턴스가 공유
  static int classVar;

  public void method() {
    // 지역 변수: 스택 영역에 생성되며, 호출 시점에 생성되고 메서드 종료 시 소멸함
    int localVar = 10;

    System.out.println(instanceVar); // 출력: 0 (자동 초기화)
    System.out.println(classVar);    // 출력: 0 (자동 초기화)
    System.out.println(localVar);    // 출력: 10 (명시적 초기화 필요)
  }
}
```

# 12. 객체지향 심화 - 상속(Inheritance)

## 12.1 상속의 개념
상속은 객체지향[^4] 프로그래밍의 핵심 개념 중 하나로, 기존에 정의되어 있는 클래스의 모든 필드와 메서드를 새로운 클래스가 물려받아 사용하는 것을 의미함. 이때 상속을 해주는 기존 클래스를 부모 클래스(상위 클래스, Super Class)라 하고, 상속을 받는 새로운 클래스를 자식 클래스(하위 클래스, Sub Class)라고 함.

### 12.1.1 상속의 특징과 장점
- 코드의 재사용성 향상: 이미 작성되어 검증된 부모 클래스의 코드를 재사용하므로 중복 코드가 줄어들고 개발 시간이 단축됨
- 유지보수성 향상: 부모 클래스의 수정만으로 이를 상속받은 모든 자식 클래스에 변경 사항이 반영되므로 일관성 있는 수정이 가능함
- 다형성[^2] 구현의 기반: 부모 클래스 타입의 참조 변수로 다양한 자식 클래스 객체를 참조할 수 있어, 확장성 높은 프로그램 설계가 가능함
- 단일 상속 지원: 자바는 다중 상속에서 발생할 수 있는 메서드 호출의 모호성(다이아몬드 문제)을 방지하기 위해 클래스의 단일 상속만 지원함. 즉, extends 뒤에는 단 하나의 클래스만 선언할 수 있음

### 12.1.2 상속 선언 형식
자식 클래스를 선언할 때 부모 클래스 뒤에 extends 키워드를 붙여서 상속 관계를 설정함.

```java
[접근제어자] class 자식클래스명 extends 부모클래스명 {
  // 필드 및 메서드 선언
}
```

### 12.1.3 상속 구현 예시
```java
public class Animal {
  public void eat() {
    System.out.println("냠냠 먹는다");
  }
}

public class Dog extends Animal {
  public void bark() {
    System.out.println("멍멍!");
  }
}

public class Test {
  public static void main(String[] args) {
    Dog dog = new Dog();
    dog.eat();  // 부모로부터 물려받은 메서드 호출
    dog.bark(); // 자신의 메서드 호출
  }
}
```

## 12.2 메서드 오버라이딩
부모 클래스로부터 상속받은 메서드의 내부 구현을 자식 클래스에서 필요에 맞게 재정의하는 기법

### 12.2.1 메서드 오버라이딩의 성립 조건
- 메서드 시그니처 일치: 부모 클래스의 메서드와 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 동일해야 함.
  ```java
  class Animal {
    public void sound() {
      System.out.println("동물이 소리를 낸다");
    }
  }

  class Dog extends Animal {
    // 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 모두 일치하므로 오버라이딩 성립
    public void sound() {
      System.out.println("멍멍!");
    }

    // 매개변수가 달라지면 오버라이딩이 아닌 오버로딩이 됨
    public void sound(int count) {
      for (int i = 0; i < count; i++) {
        System.out.println("멍멍!");
      }
    }
  }

  class Cat extends Animal {
    // 메서드 이름, 매개변수 타입 및 개수, 반환 타입이 모두 일치하므로 오버라이딩 성립
    public void sound() {
      System.out.println("야옹~");
    }
  }
  ```

- 접근 제어자[^5] 제한: 자식 클래스에서 오버라이딩[^6]하는 메서드의 접근 제어자[^5]는 부모 클래스의 메서드보다 좁은 범위로 변경할 수 없음. (예: 부모 메서드가 protected이면 자식은 protected 또는 public만 가능)
  ```java
  class Animal {
    protected void breathe() {
      System.out.println("숨을 쉽니다");
    }
  }

  class Dog extends Animal {
    // protected 또는 public으로만 오버라이딩 가능
    public void breathe() {
      System.out.println("강아지가 숨을 쉽니다");
    }

    // 부모 메서드(protected)보다 좁은 접근 제어자(default, private)로는 오버라이딩 불가 (컴파일 에러)
    // void breathe() {} 
  }
  ```

- static, final, private 메서드는 오버라이딩[^6] 불가
  ```java
  class Animal {
    private void sleep() {
      System.out.println("잠을 잡니다");
    }

    public final void live() {
      System.out.println("살아있습니다");
    }

    public static void info() {
      System.out.println("동물 정보");
    }
  }

  class Dog extends Animal {
    // private 메서드는 자식 클래스에서 접근할 수 없으므로 오버라이딩 불가. 아래 메서드는 Dog 클래스 고유의 메서드 정의임
    public void sleep() {
      System.out.println("강아지가 잠을 잡니다");
    }

    // final 메서드는 재정의할 수 없으므로 오버라이딩 불가 (컴파일 에러)
     // public void live() {}

    // static 메서드는 클래스 수준에 소속되므로 오버라이딩 불가. 아래는 메서드 가리기(Shadowing)에 해당함
    public static void info() {
      System.out.println("강아지 정보");
    }
  }
  ```

### 12.2.2 메서드 오버라이딩을 사용하는 이유와 장점
- 자식 클래스에 특화된 동작 구현: 부모 클래스의 일반적인 기능을 자식 클래스만의 구체적인 특성에 맞추어 재구성할 수 있음
  ```java
  class Animal {
    public void sound() {
      System.out.println("동물이 소리를 낸다");
    }
  }

  class Dog extends Animal {
    // 부모의 sound()가 일반적인 동작을 한다면 자식(Dog)은 "멍멍!"으로 재정의함
    @Override
    public void sound() {
      System.out.println("멍멍!");
    }
  }

  class Cat extends Animal {
    // 부모의 sound()가 일반적인 동작을 한다면 자식(Cat)은 "야옹~"으로 재정의함
    @Override
    public void sound() {
      System.out.println("야옹~");
    }
  }
  ```
- 다형성[^2] 구현의 핵심: 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스[^1]의 오버라이딩[^6]된 메서드가 자동으로 호출되므로 다형성[^2]을 실현할 수 있음
  ```java
  public class PolymorphismTest {
    public static void main(String[] args) {
      // 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스의 오버라이딩된 메서드가 실행됨
      Animal pet1 = new Dog();
      Animal pet2 = new Cat();

      pet1.sound(); // Dog의 오버라이딩된 sound()가 실행됨 (출력: 멍멍!)
      pet2.sound(); // Cat의 오버라이딩된 sound()가 실행됨 (출력: 야옹~)
    }
  }
  ```
- 코드의 유지보수성과 확장성 향상: 부모 클래스의 틀 안에서 자식 클래스들이 서로 다른 구현을 갖게 하므로, 기존 코드를 수정하지 않고도 새로운 기능을 쉽게 확장할 수 있음
  ```java
  // 기존 Animal, Dog나 Cat 클래스의 수정 없이 Snake 클래스만 새로 추가하여 확장함
  class Snake extends Animal {
    @Override
    public void sound() {
      System.out.println("쉭쉭~");
    }
  }

  public class PolymorphismTest {
    public static void main(String[] args) {
      // 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스의 오버라이딩된 메서드가 실행됨
      // Animal pet = new Dog();
      Animal pet = new Snake();

      pet.sound(); // 객체가 바뀌어도 이 코드는 수정하지 않음    
    }
  }
  ```

### 12.2.3 오버라이딩(Overriding) vs 오버로딩(Overloading) 비교

| 구분 | 메서드 오버라이딩[^6] (Overriding) | 메서드 오버로딩[^7] (Overloading) |
| :--- | :--- | :--- |
| 정의 | 상속받은 부모의 메서드를 자식 클래스에서 재정의 | 한 클래스 내에서 같은 이름의 메서드를 다중 정의 |
| 메서드 이름 | 부모 메서드와 동일함 | 동일함 |
| 매개변수 | 동일함 (개수, 타입, 순서) | 달라야 함 (개수 또는 타입 또는 순서) |
| 반환 타입 | 동일해야 함 | 상관없음 |
| 접근 제어자[^5] | 부모보다 좁아질 수 없음 | 상관없음 |

### 12.2.4 메서드 오버라이딩 구현 예시
- 부모 클래스의 기능을 자식 클래스에서 재정의하고 다형성[^2]을 활용하여 호출하는 예시

```java
// 부모 클래스 정의
class Animal {
  public void sound() {
    System.out.println("동물이 소리를 낸다");
  }
}

// 자식 클래스에서 부모 메서드 재정의
class Dog extends Animal {
  public void sound() {
    System.out.println("멍멍!");
  }
}

// 또 다른 자식 클래스에서 부모 메서드 재정의
class Cat extends Animal {
  public void sound() {
    System.out.println("야옹~");
  }
}

public class OverridingTest {
  public static void main(String[] args) {
    // 부모 타입 참조 변수로 자식 객체를 참조 (업캐스팅)
    Animal myDog = new Dog();
    Animal myCat = new Cat();

    // 실제 인스턴스에 오버라이딩된 메서드가 알아서 호출됨
    myDog.sound(); // 출력: 멍멍!
    myCat.sound(); // 출력: 야옹~
  }
}
```

## 12.3 super와 super()
상속 관계에서 자식 객체 내부에는 부모 객체의 필드와 메서드가 함께 포함되므로, 이를 명확히 구분하고 생성자 흐름을 제어하기 위해 사용하는 참조 키워드

### 12.3.1 super 참조 변수
- 자식 클래스에서 부모 클래스의 필드나 메서드에 접근할 때 사용하는 참조 변수
- 멤버 변수 가려짐(Shadowing) 해결: 자식 클래스에서 부모 클래스와 동일한 이름의 필드를 선언했을 때, 자식 클래스 내부에서 이름만으로 접근하면 자식 필드가 우선하므로 부모 필드에 접근하기 위해 super.필드명을 명시적으로 사용함

### 12.3.2 super() 생성자 호출
- 부모 클래스의 생성자를 호출하는 함수
- 자식 객체 생성 시 생성자 호출 순서: 자식 클래스의 생성자가 호출되면 내부적으로 가장 먼저 부모 클래스의 생성자가 실행되어 부모 필드가 초기화된 후, 자식 생성자의 나머지 코드가 실행됨
- 첫 줄 배치 제약: super()는 자식 클래스 생성자 코드의 첫 번째 줄에만 위치할 수 있음. 생략할 경우 컴파일러가 생성자 첫 줄에 자동으로 super()를 주입함
  + Java 25 부터는 생성자의 어느곳에 위치해 있어도 상관없음. 단, 인스턴스[^1] 생성 후에 만 사용 가능한 this나 인스턴스[^1] 메서드의 호출보다는 먼저 작성해야 함.
- 기본 생성자가 없는 경우의 제약: 부모 클래스에 매개변수가 있는 생성자만 존재하고 기본 생성자가 정의되어 있지 않았다면, 컴파일러가 자동 삽입하는 super()는 에러를 유발하므로(부모에 존재하지 않는 기본 생성자를 호출하므로) 자식 생성자에서 직접 부모의 매개변수 생성자를 호출(super(인수, ...))하도록 명시해야 함

### 12.3.3 super와 super() 활용 예시
```java
class Parent {
  String name = "부모 필드";

  Parent() {
    System.out.println("부모 기본 생성자 호출");
  }

  Parent(String name) {
    this.name = name;
    System.out.println("부모 매개변수 생성자 호출");
  }
}

class Child extends Parent {
  String name = "자식 필드"; // 부모 필드와 이름이 같음 (Shadowing)

  Child() {
    super(); // 부모 기본 생성자 호출 (생략 가능)
    System.out.println("자식 생성자 호출");
  }

  Child(String parentName, String childName) {
    super(parentName); // 부모의 매개변수 생성자를 직접 지정하여 호출
    this.name = childName;
    System.out.println("자식 매개변수 생성자 호출");
  }

  void printNames() {
    // super와 this를 통해 부모 필드와 자식 필드를 구분하여 참조
    System.out.println("부모 name: " + super.name);
    System.out.println("자식 name: " + this.name);
  }
}
```

## 12.4 final 키워드와 상속
final 키워드는 대상에 따라 변경 불가능하도록 최종적인 상태로 확정하는 제약을 부여함.

### 12.4.1 final 변수
- 변수 선언 시 final이 붙으면 상수가 되어 한 번 결정된 값을 수정할 수 없음

### 12.4.2 final 메서드
- 메서드 선언 시 final이 붙으면 자식 클래스에서 해당 메서드를 오버라이딩[^6]하여 재정의할 수 없음. 부모가 정의한 기능 그대로만 사용하도록 제한할 때 유용함

### 12.4.3 final 클래스
- 클래스 선언 시 final이 붙으면 더 이상 상속의 부모 클래스가 될 수 없음. 즉, 자식 클래스를 생성할 수 없도록 클래스 계층 구조를 제한함 (대표적으로 java.lang.String 클래스가 final 클래스)

### 12.4.4 final 키워드 예시
```java
// final 클래스는 부모 클래스가 될 수 없음 (상속 불가)
public final class FinalClass {
  // final 변수는 값 변경이 불가능한 상수
  public static final double PI = 3.14159;

  // final 메서드는 자식 클래스에서 재정의할 수 없음
  public final void printPI() {
    System.out.println(PI);
  }
}
```

## 12.5 Object 클래스
자바에서 생성되는 모든 클래스는 별도의 extends 선언이 없더라도 기본적으로 java.lang.Object 클래스를 최상위 부모로 상속받음.

### 12.5.1 모든 클래스의 최상위 부모 Object
- 상속 계층의 최상위: 어떤 클래스든 결국 Object 클래스가 자식이 되므로 자바의 모든 객체는 Object 타입으로 선언이 가능함
- 공통 기능 제공: Object 클래스는 모든 객체가 기본적으로 가져야 할 공통 메서드를 제공함

### 12.5.2 Object의 주요 메서드 재정의
- toString(): 객체의 문자열 정보를 반환하는 메서드로, 기본 구현은 클래스명과 해시코드를 출력하지만 개발 시 멤버 필드 값을 출력하도록 재정의하여 디버깅에 활용함
- equals(Object obj): 두 객체의 동등성(내용이 같은지 여부)을 비교하는 메서드로, 기본 구현은 주소값 비교(==)이지만 논리적 내용 비교가 필요한 경우 재정의함
- hashCode(): 객체의 고유한 정수 해시코드를 반환하는 메서드이며, equals 메서드를 재정의할 때 동등한 객체는 동일한 해시코드를 반환해야 한다는 규약에 따라 함께 재정의하는 것이 관례임
  + 해시 (Hash): 임의의 크기를 가진 데이터를 고정된 크기의 고유한 값(해시값)으로 변환하는 기술
    - 입력값이 같으면 항상 동일한 해시값을 반환하며, 출력된 해시값을 통해 역으로 원래 데이터를 유추할 수 없는 단방향성을 가짐
    - HashMap이나 HashSet 같은 해시 기반 자료구조[^8]에서는 객체의 해시값(hashCode())을 내부 저장소(버킷)의 인덱스로 활용하여 데이터 추가, 삭제, 검색 성능을 획기적으로 향상시킴

### 12.5.3 Object 메서드 오버라이딩 예시
- 국제 표준 도서 번호(isbn)가 같으면 도서 제목이나 저자 정보가 일부 다르더라도 동일한 도서로 판단하도록 equals와 hashCode를 재정의하는 예시

```java
public class Book {
  private String isbn; // 국제 표준 도서 번호 (예: 9788965402602)
  private String title;
  private String author;

  public Book(String isbn, String title, String author) {
    this.isbn = isbn;
    this.title = title;
    this.author = author;
  }

  // toString 오버라이딩: 객체의 정보를 가독성 있게 표현
  @Override
  public String toString() {
    return "Book[isbn=" + isbn + ", title=" + title + ", author=" + author + "]";
  }

  // equals 오버라이딩: isbn이 같으면 논리적으로 동일한 객체로 판별
  @Override
  public boolean equals(Object obj) {
    // 주소값이 같으면 동일한 객체임
    if (this == obj) {
      return true;
    }
    // instanceof: 객체가 Book 클래스의 인스턴스인지 검사하여 타입 안정성 확보
    if (obj instanceof Book) {
      Book other = (Book) obj; // 다운캐스팅
      return this.isbn != null && this.isbn.equals(other.isbn);
    }
    return false;
  }

  // equals를 재정의할 때 hashCode도 동일한 기준(isbn)으로 함께 재정의해야 함
  @Override
  public int hashCode() {
    return isbn != null ? isbn.hashCode() : 0;
  }
}

public class BookTest {
  public static void main(String[] args) {
    // isbn이 동일한 두 개의 Book 객체 생성 (동일 도서의 다른 지점 소장본 상황)
    Book b1 = new Book("9788965402602", "자바를 잡아라", "용쌤");
    Book b2 = new Book("9788965402602", "자바를 잡아라 (개정판)", "용쌤");

    // toString() 오버라이딩 결과 확인
    System.out.println(b1); // 출력: Book[isbn=9788965402602, title=자바를 잡아라, author=용쌤]
    System.out.println(b2); // 출력: Book[isbn=9788965402602, title=자바를 잡아라 (개정판), author=용쌤]

    // equals() 오버라이딩을 통해 논리적 동등성 비교 (isbn이 같으므로 true)
    System.out.println("두 도서가 동등한가요? " + b1.equals(b2)); // 출력: 두 도서가 동등한가요? true

    // hashCode() 오버라이딩 결과 확인 (동등한 객체는 해시코드도 일치해야 함)
    System.out.println("b1 해시코드: " + b1.hashCode());
    System.out.println("b2 해시코드: " + b2.hashCode());
  }
}
```

## 12.6 클래스 관계 설계: 포함(Has-A) vs 상속(Is-A)
객체지향[^4] 설계에서 클래스를 재사용하고 확장하기 위해 두 클래스의 관계를 설정하는 대표적인 방법으로 포함과 상속이 존재.

### 12.6.1 포함 관계 (Has-A)
- 한 클래스가 다른 클래스의 인스턴스[^1]를 자신의 필드로 선언하여 소유하는 관계
- "~은 ~을 가지고 있다" (Has-A)로 자연스럽게 설명될 때 포함 관계를 선택 (예: 자동차는 엔진을 가지고 있음, 도서관은 책을 가지고 있음)

```java
public class Engine {
  void start() {
    System.out.println("엔진이 가동됨");
  }
}

public class Car {
  // Engine 객체를 필드로 선언하여 소유 (포함 관계)
  Engine engine = new Engine();

  void drive() {
    engine.start();
    System.out.println("자동차가 주행함");
  }
}
```

### 12.6.2 상속 관계 (Is-A)
- 부모 클래스의 특성을 그대로 물려받아 자식 클래스로 구체화하여 설계하는 관계
- "~은 ~이다" (Is-A)로 자연스럽게 설명될 때 상속 관계를 선택 (예: 강아지는 동물, 노트북은 컴퓨터)

```java
public class Computer {
  void powerOn() {
    System.out.println("전원이 켜짐");
  }
}

public class Laptop extends Computer {
  // 컴퓨터를 상속받아 노트북으로 확장 (상속 관계)
  void useBattery() {
    System.out.println("배터리 전원을 사용함");
  }
}
```

### 12.6.3 올바른 설계 선택 방향
- 상속의 오남용 방지: 상속은 강력한 재사용 도구이지만, 부모와 자식 간의 결합도가 매우 높아져 부모의 변경이 자식에게 큰 영향을 미침. 단순히 코드를 재사용하기 위해 억지로 상속 관계를 맺으면 설계 왜곡 가능성 존재
- Has-A 관계 우선 고려: 두 클래스의 관계가 순수한 Is-A 구조가 아니라면 대부분 포함(Has-A) 관계를 사용하는 것이 설계의 유연성을 확보하고 결합도를 낮추는 방법

# 13. 객체지향 심화 - 다형성(Polymorphism)과 인터페이스

## 13.1 다형성
- 다형성[^2]: 하나의 타입(부모 클래스나 인터페이스[^9])으로 여러 가지 객체(자식 객체)를 참조하고 제어할 수 있는 객체지향[^4]의 핵심 특징. 즉, 동일한 호출(메서드 호출)을 하더라도 참조하는 실제 인스턴스[^1]에 따라 서로 다른 결과와 동작을 나타내는 성질을 의미함

### 13.1.1 다형성 성립의 3대 조건
- 상속 관계: 클래스 간 상속(extends)이나 인터페이스[^9] 구현(implements) 구조가 선언되어 있어야 함
- 메서드 오버라이딩[^6]: 자식 클래스가 부모 클래스의 메서드를 재정의하여 자신의 기능으로 변경해 두어야 함
- 부모 타입의 참조 변수 사용: 부모 클래스나 인터페이스[^9] 타입의 변수로 자식 객체를 가리켜 제어해야 함 (업캐스팅)

### 13.1.2 업캐스팅과 다운캐스팅
- 업캐스팅: 자식 객체를 부모 타입으로 형변환하는 것 (자동 형변환)
- 다운캐스팅: 부모 타입으로 형변환된 객체를 다시 원래의 자식 타입으로 형변환하는 것 (명시적 형변환 필요)
  + 주의: 실제 생성된 인스턴스[^1] 타입과 일치하지 않는 다른 자식 타입으로 잘못 다운캐스팅할 경우 ClassCastException 예외가 런타임에 발생하므로 주의해야 함

```java
class Animal {
  public void eat() {
    System.out.println("냠냠 먹는다");
  }
}

class Dog extends Animal {
  public void eat() {
    System.out.println("강아지가 먹는다");
  }
  public void bark() {
    System.out.println("멍멍!");
  }
}

class Cat extends Animal {
  public void eat() {
    System.out.println("고양이가 먹는다");
  }
  public void meow() {
    System.out.println("야옹~");
  }
}

public class Test {
  public static void main(String[] args) {
    Animal myPet = new Dog(); // 업캐스팅: 자식 객체를 부모 타입으로 형변환
    // Dog의 오버라이딩된 eat() 실행
    myPet.eat(); // 출력: 강아지가 먹는다
    // myPet.bark(); // 메서드 호출 가능 여부는 타입에 따라서 결정되므로 에러 발생(Animal에는 bark가 없음)

    Dog namu = (Dog) myPet; // 다운캐스팅: 업캐스팅된 객체를 원래의 자식 타입으로 형변환
    namu.bark(); // 정상 작동

    // 잘못된 다운캐스팅 시도 (실제 인스턴스가 Dog이므로 Cat으로 형변환 불가)
    // 컴파일 시점에는 문법 에러가 없으나 실행(런타임) 시 ClassCastException 예외가 발생함
    // Cat myCat = (Cat) myPet; 
  }
}
```

## 13.2 instanceof 연산자
- 참조 변수가 실제로 어떤 타입의 객체를 가리키고 있는지 확인할 때 사용

```java
if (myPet instanceof Dog) {
  Dog namu = (Dog) myPet;
  namu.bark();
}
```

## 13.3 추상 클래스

### 13.3.1 추상 클래스의 개념
- 추상 클래스는 실체 클래스들의 공통적인 특성(필드, 메서드)을 추출하여 선언한 미완성 설계도
- 미완성 상태의 클래스이므로 단독으로 객체를 생성할 수 없음
- 클래스 선언부에 abstract 키워드를 붙여 정의
  ```java
  // abstract 키워드를 사용하여 추상 클래스 선언
  abstract class Animal {
    // 필드, 생성자, 메서드 선언 가능
  }
  ```

### 13.3.2 추상 클래스의 특징
- 직접적인 객체 생성 불가: 설계도 자체가 미완성이므로 new 연산자를 사용하여 단독으로 인스턴스[^1]를 생성할 수 없음
- 생성자 보유: 직접 객체를 생성할 수는 없지만, 자식 객체가 생성될 때 부모 생성자인 super()를 호출해야 하므로 생성자가 반드시 존재하고 호출됨
- 일반 멤버 포함 가능: 미완성인 추상 메서드 외에도 일반적인 필드(멤버 변수)와 완성된 바디를 가진 일반 메서드를 자유롭게 가질 수 있음

### 13.3.3 추상 메서드 (Abstract Method)
- 선언부만 있고 구현부(중괄호 블록)가 없는 메서드로, abstract 키워드를 사용하여 선언함
  ```java
  abstract class Animal {
    // 선언부만 존재하고 구현부(중괄호)가 없는 추상 메서드
    abstract void sound();
  }
  ```
- 자식 클래스에게 특정 동작의 구현을 강력하게 강제하기 위해 사용함
- 추상 클래스를 상속받은 자식 클래스는 부모의 모든 추상 메서드를 반드시 오버라이딩[^6]하여 구체적으로 구현해야 하며, 그렇지 않을 경우 자식 클래스 역시 추상 클래스로 선언해야 하므로 컴파일 에러가 발생함
  ```java
  // Animal을 상속받은 Dog 클래스는 반드시 sound() 메서드를 오버라이딩하여 구현해야 함
  class Dog extends Animal {
    @Override
    void sound() {
      System.out.println("멍멍!");
    }
  }
  ```

### 13.3.4 실체 클래스가 아닌 추상 클래스로 선언하는 이유
- 부모 클래스의 단독 객체 생성 차단: Animal이나 Shape처럼 그 자체로 실체가 없는 추상적인 개념의 클래스가 new 연산자를 통해 단독 객체로 만들어지는 실수를 방지함
- 자식 클래스의 특정 메서드 구현 강제: 일반 부모 클래스의 메서드는 자식 클래스에서 오버라이딩[^6]을 생략하더라도 문법적인 문제가 없어 실수할 여지가 있음. 반면 추상 메서드는 상속받는 자식 클래스에서 강제적으로 재정의하도록 컴파일 시점에 검증하므로 필수 규격의 누락을 원천 차단함

### 13.3.5 추상 클래스 구현 예시
- 추상 클래스인 Animal을 상속받아 자식 클래스인 Dog와 Cat을 정의하고 추상 메서드를 강제 구현하는 예시

```java
// 추상 클래스 선언
abstract class Animal {
  // 구현부가 없는 추상 메서드 선언
  abstract void sound(); // 동물의 우는 소리는 실제 자식 객체에서 구현이 가능하므로 Animal에서는 해당 메서드의 시그니처만 기술하고 내용을 구현할 수 없음
}

// 자식 클래스 Dog: 추상 클래스 Animal 상속 및 추상 메서드 구현
class Dog extends Animal {
  @Override
  void sound() {
    System.out.println("멍멍!");
  }
}

// 자식 클래스 Cat: 추상 클래스 Animal 상속 및 추상 메서드 구현
class Cat extends Animal {
  @Override
  void sound() {
    System.out.println("야옹~");
  }
}

public class AbstractTest {
  public static void main(String[] args) {
    // 1. 추상 클래스는 직접 new 연산자로 객체 생성 불가 (컴파일 에러 발생)
    // Animal animal = new Animal(); 

    // 2. 자식 클래스를 통한 객체 생성 및 부모 타입 다형성 적용
    Animal myDog = new Dog();
    Animal myCat = new Cat();

    // 각자 오버라이딩하여 구현한 추상 메서드 실행
    myDog.sound(); // 출력: 멍멍!
    myCat.sound(); // 출력: 야옹~
  }
}
```

## 13.4 인터페이스

### 13.4.1 인터페이스의 개념
인터페이스는 객체의 사용 설명서이자 극단적인 추상화 설계도임. 구현부 없이 오직 객체가 수행해야 할 동작의 규격(스펙)만을 정의해 둔 것이며, 클래스들이 가져야 할 기능의 공통 표준 규격을 마련하기 위해 사용함.

### 13.4.2 인터페이스의 문법적 특징
#### 1) 선언부 키워드
- 클래스 선언 시 사용하는 class 키워드 대신 interface 키워드를 사용하여 선언함
  ```java
  // class 키워드 대신 interface 키워드를 사용함
  interface Calculator {
    // ...
  }
  ```
#### 2) 모든 필드는 상수
- 인터페이스 내의 멤버 변수는 컴파일 시 자동으로 public static final 상수로 취급되며, 반드시 선언과 동시에 초기화해야 함
  ```java
  interface Calculator {
    // 선언과 동시에 값을 초기화해야 함 (자동으로 public static final double PI = 3.14159; 로 취급됨)
    double PI = 3.14159; 
  }
  ```
#### 3) 메서드 선언 규칙
- 인터페이스 내부의 메서드는 기본적으로 구현부(중괄호 블록)가 없는 추상 메서드로 선언됨 (자동으로 public abstract 제어자가 지정됨)
  ```java
  interface Calculator {
    // 구현부가 없는 추상 메서드 (자동으로 public abstract int calculate(int a, int b); 로 취급됨)
    int calculate(int a, int b);
  }
  ```
#### 4) 다중 구현 지원
- 자바는 클래스 상속의 단일 상속 제약을 극복하기 위해 인터페이스를 통한 다중 구현을 완벽히 지원함. 하나의 클래스가 여러 인터페이스를 implements 키워드 뒤에 콤마(,)로 나열하여 동시에 구현할 수 있음
  ```java
  interface Calculator {
    int calculate(int a, int b);
  }

  interface Printer {
    void printResult(int result);
  }

  // 두 인터페이스를 동시에 구현함
  class MultiCalculator implements Calculator, Printer {
    @Override
    public int calculate(int a, int b) {
      return a + b;
    }

    @Override
    public void printResult(int result) {
      System.out.println("결과: " + result);
    }
  }
  ```
#### 5) 객체 생성 불가
- 추상 클래스[^10]와 마찬가지로 new 연산자를 사용하여 단독으로 인스턴스[^1]화할 수 없음

### 13.4.3 인터페이스 구현과 규격 일치
- 구현 클래스는 인터페이스에 정의된 모든 추상 메서드를 반드시 오버라이딩[^6]하여 바디를 완성해야 함. 이때 인터페이스의 메서드는 묵시적으로 public이므로, 오버라이딩[^6]할 때 자식 메서드의 접근 제어자[^5]는 반드시 public이어야 함 (더 좁은 접근 권한으로 축소할 수 없음)

### 13.4.4 추상 클래스 vs 인터페이스
- 추상 클래스 (Is-A): 부모와 자식 간의 밀접한 혈연 관계를 정의하며, 상태(필드)와 일반 행위를 상속하여 공유하는 목적
- 인터페이스 (Can-Do): 혈연과 상관없이 공통적인 동작이나 특정 기능을 수행할 수 있는 능력(동작 규격)을 여러 클래스에 부여하는 목적

### 13.4.5 인터페이스 다중 구현 예시
- 날 수 있는 기능(Flyable)과 헤엄칠 수 있는 기능(Swimable)을 가진 오리(Duck) 클래스가 Animal 상속과 두 개의 인터페이스를 다중 구현하는 예시

```java
// 날 수 있는 동작 규격 정의
interface Flyable {
  void fly(); // 컴파일 시 public abstract void fly()로 자동 변환됨
}

// 헤엄칠 수 있는 동작 규격 정의
interface Swimable {
  void swim();
}

// 부모 클래스 Animal
class Animal {
  void breathe() {
    System.out.println("숨을 쉽니다.");
  }
}

// 다중 구현 클래스 Duck: Animal을 상속받으면서 Flyable, Swimable을 동시에 구현
class Duck extends Animal implements Flyable, Swimable {
  // Flyable의 추상 메서드 구현 (반드시 public 제어자 필요)
  @Override
  public void fly() {
    System.out.println("오리가 날개를 파닥이며 날아갑니다.");
  }

  // Swimable의 추상 메서드 구현
  @Override
  public void swim() {
    System.out.println("오리가 발을 저으며 물을 헤엄칩니다.");
  }
}

public class InterfaceTest {
  public static void main(String[] args) {
    Duck duck = new Duck();

    // 1. 상속받은 일반 메서드 실행
    duck.breathe(); // 출력: 숨을 쉽니다.

    // 2. 다중 구현한 인터페이스들의 메서드 실행
    duck.fly();  // 출력: 오리가 날개를 파닥이며 날아갑니다.
    duck.swim(); // 출력: 오리가 발을 저으며 물을 헤엄칩니다.

    // 3. 다형성을 이용한 인터페이스 타입 참조
    Flyable flyingDuck = duck; // 업캐스팅
    flyingDuck.fly(); // 가용한 메서드는 Flyable에 정의된 fly()로 제한됨
  }
}
```

## 13.5 인터페이스의 구현 메서드 (default, static, private)
- 자바 버전이 올라감에 따라 인터페이스의 활용도를 높이고 하위 호환성을 유지하기 위해, 바디(구현부)를 가질 수 있는 세 종류의 구현 메서드가 도입됨

### 13.5.1 default 메서드 (자바 8부터 도입)
- 기존 인터페이스에 새로운 메서드를 추가할 때, 이미 해당 인터페이스를 구현하고 있는 기존 클래스들의 수정 없이 공통적인 기본 기능을 제공하기 위해 도입됨
- 오버라이딩[^6]은 선택적이며, 선언부에 default 키워드를 명시해야 함
- 접근 제어자[^5]는 무조건 public이며 생략 시 자동으로 public으로 취급됨

### 13.5.2 static 메서드 (자바 8부터 도입)
- 객체 생성 없이 인터페이스명으로 직접 호출할 수 있는 정적 유틸리티 메서드
- 접근 제어자[^5]를 생략하는 경우 자동으로 public static으로 취급되며, 인터페이스 외부에서 직접 호출할 수 있음

### 13.5.3 private 메서드 (자바 9부터 도입)
- 인터페이스 내부의 default 또는 static 메서드 내에서만 호출 가능한 비공개 보조 메서드임
- 구현 메서드 간의 공통 코드를 분리하여 코드 중복을 방지하기 위해 도입됨
- 명시적으로 private 접근 제어자[^5]를 선언하며, default 키워드는 붙이지 않음

### 13.5.4 인터페이스 구현 메서드 적용 예시
```java
interface Calculator {
  // 1. 추상 메서드
  int calculate(int a, int b);

  // 2. default 메서드 (자바 8부터 지원, 오버라이딩 선택 가능)
  default void printResult(int result) {
    log("결과 출력: " + result); 
  }

  // 3. static 메서드 (자바 8부터 지원, 인터페이스명으로 직접 호출)
  static int add(int a, int b) {
    return a + b;
  }

  // 4. private 메서드 (자바 9부터 지원, 내부 보조용으로만 사용)
  private void log(String msg) {
    System.out.println("[로그] " + msg);
  }
}

// Calculator를 구현하는 클래스
class SimpleCalculator implements Calculator {
  @Override
  public int calculate(int a, int b) {
    return a * b; // 곱셈으로 구현함
  }
}

public class InterfaceMethodTest {
  public static void main(String[] args) {
    Calculator calc = new SimpleCalculator();

    // 1. 추상 메서드 호출
    int res = calc.calculate(5, 4);

    // 2. default 메서드 호출
    calc.printResult(res); // 출력: [로그] 결과 출력: 20

    // 3. static 메서드 호출 (인터페이스명으로 직접 호출함)
    int sum = Calculator.add(5, 4);
    System.out.println("정적 메서드 합계: " + sum); // 출력: 정적 메서드 합계: 9
  }
}
```

# 14. 자바 주요 패키지와 API

자바는 풍부한 표준 라이브러리(Application Programming Interface)를 탑재하고 있어, 개발자가 유용한 기능들을 직접 구현하지 않고도 미리 만들어진 클래스들을 가져와 편리하게 사용 가능

## 14.1 자바 API 문서
자바 API 문서(Java API Specification)는 자바가 표준으로 설계하여 탑재해 둔 수천 개의 클래스, 인터페이스, 메서드들의 상세 명세서(사용 가이드, 파라미터, 반환 규격)를 정리한 공식 온라인 문서.

```java
public class ApiDocumentTest {

  }
```

### 14.1.1 공식 API 문서 확인
- 오라클 공식 자바 표준 문서 저장소: https://docs.oracle.com/en/java/javase/
- JDK 버전을 선택한 후 API Documentation 확인
- API 문서가 매우 방대하므로 검색 기능을 주로 활용

### 14.1.2 공식 문서를 통한 String 클래스 분석
- 클래스 기본 명세 확인: java.lang.String 클래스가 최상위 클래스인 Object로부터 어떻게 파생되었는지 상속 계층도(Hierarchy) 확인
- 구현하는 인터페이스 확인: String 클래스가 Comparable 이나 Serializable 같은 표준 인터페이스들을 구현하는지 확인
- Constructor Summary (생성자 요약): 다양한 매개변수를 받는 여러 생성자들의 리스트와 그에 따른 오버로딩 설계 확인
- Method Summary (메서드 요약):
  - Modifier and Type: 해당 메서드가 static으로 공유되는 메서드인지, 혹은 일반 인스턴스 메서드인지와 리턴되는 타입(int, boolean, String 등)을 확인
  - Method and Description: 메서드명과 매개변수를 매핑하여, 어떠한 기능을 수행하고 예외 상황 시 어떤 동작을 하는지 확인
  - Throws: 메서드 사용 중 파라미터 유효성에 문제가 생길 때(예: NullPointerException) 어떤 내부 예외를 개발자에게 호출하여 던져주는지 확인

## 14.2 주요 패키지 개요
자바 표준 클래스들은 용도와 기능별로 묶여서 패키지 형태로 제공. 대표적인 핵심 패키지는 다음과 같음.

- java.lang: 자바 프로그래밍의 가장 기본적인 클래스들을 담고 있는 패키지. 이 패키지의 클래스들은 import 구문 없이도 자동으로 사용 가능 (예: System, String, Object, Math 등)

```java
// java.lang 패키지의 클래스는 import 없이 사용 가능

import java.util.ArrayList;

  }
}
```

## 14.3 문자열 클래스 (String, StringBuffer, StringBuilder)

### 14.3.1 String 클래스의 내부 메커니즘과 불변성 (Immutability)
- String 객체는 한 번 생성되면 메모리 상에서 내부 값을 변경할 수 없는 불변 객체임

#### 1) 문자열 상수 풀 (String Constant Pool)
- 메모리 효율성과 안정성을 위해 힙 메모리 내부에 특수한 공유 메모리를 구성
- 리터럴 선언 시 상수 풀에서 동일 문자열 확인 후 참조, 내용 비교를 위해 equals 사용 권장

#### 2) 문자열 결합 연산의 부작용
- (+) 연산 시 새로운 문자열 객체가 생성되어 임시 객체가 힙 영역에 쌓임
- 루프 내 반복 연산 시 가비지 컬렉터 성능 저하 초래

```java
public class StringImmutabilityTest {
  public static void main(String[] args) {
    String s1 = "Hello";
    String s2 = "Hello";
    String s3 = new String("Hello");

    // 문자열 리터럴 주소 비교 (참조 풀 활용)
    System.out.println(s1 == s2); // true

    // new를 통한 신규 생성 주소 비교
    System.out.println(s1 == s3); // false

    // 문자열 내용 비교 (equals 권장)
    System.out.println(s1.equals(s3)); // true
  }
}
```

### 14.3.2 가변 문자열 클래스: StringBuffer와 StringBuilder
- 문자열의 잦은 편집이 일어나는 프로그램에서 힙 공간 낭비 방지를 위한 가변 객체 클래스 사용

#### 1) StringBuffer
- 멀티스레드 환경에서 안전한 동기화(Thread-safe) 처리

#### 2) StringBuilder
- 동기화 처리가 생략된 싱글스레드 환경 최적화 클래스
- 웹 백엔드의 로컬 변수 조작 등에서 속도 최적화를 위해 주로 사용

```java
public class StringBuilderTest {
  public static void main(String[] args) {
    StringBuilder sb = new StringBuilder("Hello");
    sb.append(" World"); // 문자열 결합 시 객체를 새로 생성하지 않음
    sb.insert(5, ",");  // 문자열 삽입
    System.out.println(sb.toString()); // 출력: Hello, World
  }
}
```

### 14.3.3 String 주요 메서드
- length(): 문자열 총 길이 반환
- charAt(int index): 특정 인덱스 문자 반환
- substring(int begin, int end): 시작부터 끝 직전까지 문자열 반환
- equals(Object obj): 내용 일치 여부 반환
- indexOf(String str): 처음 시작하는 인덱스 반환
- replace(CharSequence target, CharSequence replacement): 치환된 새 문자열 반환
- split(String regex): 구분 기호 기준으로 분리된 배열 반환

```java
public class StringMethodsTest {
  public static void main(String[] args) {
    String text = "Java Programming";

    System.out.println(text.length()); // 16
    System.out.println(text.charAt(5)); // P
    System.out.println(text.substring(5, 12)); // Program
    System.out.println(text.indexOf("Pro")); // 5
    System.out.println(text.replace("Java", "Modern Java")); // Modern Java Programming

    String[] words = text.split(" ");
    System.out.println(words[0]); // Java
  }
}
```

### 14.3.4 StringBuffer 주요 메서드
- append(String str): 끝 부분에 문자열 추가
- insert(int offset, String str): 특정 위치 문자열 삽입

```java
public class StringBufferTest {
```

## 14.4 래퍼 클래스 (Wrapper Class)
- 기본 자료형(Primitive Type)의 데이터를 객체로 다루기 위한 클래스

### 14.4.1 기본 자료형과 래퍼 클래스 매핑

| 기본 자료형 (Primitive Type) | 래퍼 클래스 (Wrapper Class) |
| :--- | :--- |
| byte | Byte |
| short | Short |
| int | Integer |
| long | Long |
| float | Float |
| double | Double |
| char | Character |
| boolean | Boolean |

### 14.4.2 박싱(Boxing)과 언박싱(Unboxing)
- 박싱: 기본 자료형을 래퍼 객체로 변환
- 언박싱: 래퍼 객체를 기본 자료형으로 변환
- 자바 5부터 오토 박싱(Auto-boxing) 및 오토 언박싱(Auto-unboxing) 지원

```java
// 명시적 박싱과 언박싱 (예전 방식)
Integer num1 = Integer.valueOf(100);
int value1 = num1.intValue();

// 오토 박싱과 오토 언박싱 (자바 5 이후)
Integer num2 = 100; // 자동 박싱
int value2 = num2; // 자동 언박싱
```

### 14.4.3 주요 문자열 변환 정적 메서드
- Integer.parseInt(String s): 문자열 정수 변환
- Double.parseDouble(String s): 문자열 실수 변환
- Boolean.parseBoolean(String s): 문자열 논리값 변환

```java
public class WrapperParsingTest {

    int num = Integer.parseInt("123");

    boolean flag = Boolean.parseBoolean("true");

  }
}
```

## 14.5 Math 클래스
- 수학 계산에 유용한 정적 상수와 정적 메서드 제공, 인스턴스 생성 불가

### 14.5.1 주요 정적 메서드
- Math.abs(): 절대값 계산
- Math.max(): 큰 값 반환

# 16. 모던 자바 - 람다(Lambda)와 함수형 프로그래밍

## 16.1 함수형 프로그래밍이란?
- 상태 변경을 피하고 순수 함수를 조합하여 프로그램을 작성하는 패러다임
- 자바 8부터 람다식을 통해 함수를 일급 객체처럼 다룰 수 있게 됨

```java
public class PureFunctionTest {
  // 입력값이 같으면 항상 같은 결과를 반환하는 순수 함수
  public static int add(int a, int b) {
    return a + b;
  }

  public static void main(String[] args) {
    int result = add(3, 5);
    System.out.println(result); // 8
  }
}
```

## 16.2 람다식 문법
- 메서드의 이름과 반환타입을 생략하고 화살표 `->` 를 이용
- `(매개변수) -> { 실행문; }`

```java
// 기존 익명 클래스
Runnable r1 = new Runnable() {
  public void run() {
    System.out.println("달린다");
  }
};

// 람다식 적용
Runnable r2 = () -> System.out.println("달린다");
```

## 16.3 표준 함수형 인터페이스
자바 라이브러리(`java.util.function`)에서 자주 쓰이는 패턴을 미리 정의해 두었음.
- `Predicate<T>`: 매개변수를 받아 `boolean`을 반환
- `Consumer<T>`: 매개변수를 받아서 소모만 하고 반환하지 않음 (`void`)
- `Function<T, R>`: 매개변수를 받아서 다른 타입으로 변환하여 반환
- `Supplier<T>`: 매개변수 없이 값을 제공

```java
import java.util.function.*;

public class FunctionalInterfaceTest {
  public static void main(String[] args) {
    // Predicate: 입력값이 짝수인지 검사
    Predicate<Integer> isEven = num -> num % 2 == 0;
    System.out.println(isEven.test(4)); // true

    // Consumer: 입력값 출력
    Consumer<String> printer = str -> System.out.println(str);
    printer.accept("Java Consumer");

    // Function: 문자열을 정수로 변환
    Function<String, Integer> parser = Integer::parseInt;
    System.out.println(parser.apply("100") + 50); // 150
  }
}
```

## 16.4 메서드 참조
- 람다식이 단 하나의 메서드만 호출할 때 코드를 더 간결하게 줄이는 문법 `클래스명::메서드명`

```java
// 람다
Consumer<String> printer = s -> System.out.println(s);
// 메서드 참조
Consumer<String> betterPrinter = System.out::println;
```

## 16.5 어노테이션(Annotation)
자바 프로그래밍에서 어노테이션은 소스코드에 부가적인 정보를 담는 메타데이터의 일종으로, 컴파일러나 프레임워크, 런타임 환경에 특정 지시를 전달하는 역할을 수행.

### 16.5.1 어노테이션의 역할과 종류
- 컴파일러 지시: 코드 컴파일 시점에 오류를 잡아내거나 경고를 억제하기 위한 정보를 컴파일러에 전달
- 빌드 및 배포 도구 지원: 코드 빌드 시 XML 설정 파일을 생성하거나 코드를 자동으로 구성하는 데 활용
- 실행 시점 제어: 런타임에 리플렉션 기술을 통해 특정 클래스나 메서드의 동작을 동적으로 제어

### 16.5.2 대표적인 표준 어노테이션
- @Override: 선언된 메서드가 부모 클래스나 인터페이스의 메서드를 올바르게 재정의했는지 컴파일러가 유효성을 검사하도록 요청
- @FunctionalInterface: 인터페이스가 람다식 구현에 적합한 함수형 인터페이스(추상 메서드가 단 하나만 존재)인지 컴파일러가 검증하도록 제약
- @Deprecated: 더 이상 사용하지 않거나 향후 버전에서 제거될 수 있는 대상임을 표시하여, 해당 메서드 사용 시 컴파일러 경고를 표시

### 16.5.3 어노테이션 선언 및 적용 예시
```java
// 함수형 인터페이스임을 검증하는 어노테이션 적용
@FunctionalInterface
public interface CustomRunner {
  void run();
}

public class AnnotationExample {
  // 사용을 권장하지 않는 메서드임을 경고하는 어노테이션 적용
  @Deprecated
  public void oldMethod() {
    System.out.println("구형 메서드임");
  }
}
```

# 17. 데이터 가공 - 스트림(Stream) API

## 17.1 스트림 API 개념
- 컬렉션의 데이터들을 파이프라인 형태로 연결하여 필터링, 매핑 등의 처리를 선언형으로 작성하는 기능

```java
import java.util.*;

public class StreamConceptTest {
  public static void main(String[] args) {
    List<String> list = Arrays.asList("a", "b", "c");
    // 스트림을 이용한 선언형 출력
    list.stream().forEach(System.out::println);
  }
}
```

## 17.2 스트림 파이프라인 3단계
1. 생성: 컬렉션이나 배열에서 스트림을 엶
2. 중간 연산: 데이터를 필터링하거나 변환 (여러 개 연결 가능)
3. 최종 연산: 결과를 수집하거나 순회하며 스트림을 닫음

```java
import java.util.*;

public class StreamPipelineTest {
  public static void main(String[] args) {
    List<Integer> list = Arrays.asList(1, 2, 3, 4, 5);

    long count = list.stream()          // 1. 생성
                     .filter(n -> n > 2) // 2. 중간 연산
                     .count();           // 3. 최종 연산

    System.out.println("3보다 큰 수의 개수: " + count); // 3
  }
}
```

## 17.3 주요 중간 연산
- `filter()`: 조건에 맞는 요소만 남김
- `map()`: 요소를 다른 형태로 변환
- `flatMap()`: 중첩된 구조를 평탄화
- `sorted()`: 요소를 정렬
- `distinct()`: 중복을 제거

```java
import java.util.*;

public class StreamIntermediateTest {
  public static void main(String[] args) {
    List<String> list = Arrays.asList("a", "b", "a", "c", "b");

    list.stream()
        .distinct() // 중복 제거
        .sorted()   // 정렬
        .map(String::toUpperCase) // 대문자로 매핑
        .forEach(System.out::println); // 출력: A, B, C
  }
}
```

## 17.4 주요 최종 연산
- `forEach()`: 각 요소를 순회하며 소비
- `collect()`: 결과를 리스트나 맵 등으로 변환하여 수집
- `count()`, `sum()`, `max()`, `min()`: 집계 연산을 수행

```java
List<String> names = Arrays.asList("Kim", "Park", "Lee", "Kang", "Koo");

List<String> result = names.stream()
.filter(name -> name.startsWith('K'))
.map(String::toUpperCase)
.collect(Collectors.toList());

System.out.println(result); // [KIM, KANG, KOO]
```

## 17.5 지연 연산(Lazy Evaluation)
- 최종 연산이 호출되기 전까지 중간 연산은 실행을 미루며 대기
- 최종 연산이 호출될 때 최적의 경로로 한 번에 처리하여 성능을 높임

```java
import java.util.*;

public class StreamLazyEvaluationTest {
  public static void main(String[] args) {
    List<Integer> list = Arrays.asList(1, 2, 3);

    list.stream()
        .filter(n -> {
          System.out.println("filter: " + n);
          return n > 1;
        }); // 최종 연산이 없으므로 "filter: " 문구가 콘솔에 출력되지 않음
  }
}
```

# 18. 예외 처리(Exception)

## 18.1 에러와 예외
- 에러(Error): 메모리 부족 등 프로그램 코드로 수습할 수 없는 심각한 시스템 문제
- 예외(Exception): 프로그램 코드로 수습 가능한 비교적 덜 심각한 오류

```java
public class ExceptionTest {
  public static void main(String[] args) {
    // 0으로 나누기 시도 시 ArithmeticException 예외 발생
    int result = 10 / 0;
  }
}
```

## 18.2 예외 클래스의 계층 구조
- 모든 예외의 최고 조상은 `Exception` 클래스
- `RuntimeException`과 그 하위 클래스(Unchecked 예외): 컴파일러가 예외 처리를 강제하지 않음
- 그 외의 `Exception` (Checked 예외): 반드시 `try-catch`로 묶어주거나 예외를 전가해야 컴파일됨

```java
import java.io.*;

public class CheckedExceptionTest {
  public static void main(String[] args) {
    // FileReader 생성자는 checked exception(FileNotFoundException)을 선언하고 있어
    // 예외 처리를 강제함 (try-catch 혹은 throws 필요)
    try {
      FileReader reader = new FileReader("nonexistent_file.txt");
    } catch (FileNotFoundException e) {
      System.out.println("파일을 찾을 수 없습니다.");
    }
  }
}
```

## 18.3 try-catch-finally 블록
```java
try {
  int result = 10 / 0; // 예외 발생
} catch (ArithmeticException e) {
  System.out.println("0으로 나눌 수 없음");
} finally {
  System.out.println("예외 발생 여부와 상관없이 무조건 실행됨");
}
```

## 18.4 throws와 throw
- `throws`: 메서드 선언부에 사용하여, 이 메서드에서 발생할 수 있는 예외를 호출한 곳으로 떠넘김
- `throw`: 개발자가 고의로 예외 객체를 생성하여 발생

```java
public class ThrowsTest {
  // 예외를 호출 부로 떠넘기기
  public static void checkAge(int age) throws IllegalArgumentException {
    if (age < 0) {
      // 예외 직접 발생시키기
      throw new IllegalArgumentException("나이는 음수가 될 수 없습니다.");
    }
  }

  public static void main(String[] args) {
    try {
      checkAge(-5);
    } catch (IllegalArgumentException e) {
      System.out.println(e.getMessage());
    }
  }
}
```

## 18.5 사용자 정의 예외
- 비즈니스 로직에 맞는 구체적인 예외 상황을 표현하기 위해 커스텀 예외 클래스 생성 가능

```java
// 사용자 정의 예외 선언
```

# 19. 소프트웨어 품질과 TDD 철학

## 19.1 단위 테스트(Unit Test)
- 작성한 코드가 의도대로 동작하는지 가장 작은 단위로 쪼개어 검증하는 것
- 부작용을 조기 발견하고 리팩토링 시 안전망 역할을 함

```java
// 테스트 대상 클래스
class Calculator {
  public int add(int a, int b) {
    return a + b;
  }
}

// 단위 테스트 로직 예시 (JUnit 없이 수동 검증)
public class ManualTest {
  public static void main(String[] args) {
    Calculator calc = new Calculator();
    int result = calc.add(10, 20);
    if (result == 30) {
      System.out.println("단위 테스트 통과");
    } else {
      System.out.println("단위 테스트 실패");
    }
  }
}
```

## 19.2 JUnit 프레임워크 기초
- 자바 생태계의 표준 테스트 프레임워크
- 특정 규격에 맞춰 테스트 메서드를 작성하여 동작을 검증함

```java
import static org.junit.jupiter.api.Assertions.assertEquals;

public class CalculatorTest {
  void 더하기_테스트() {
    Calculator calc = new Calculator();
    int result = calc.add(2, 3);
    assertEquals(5, result);
  }
}
```

## 19.3 TDD 3단계 사이클
- TDD는 실제 코드 작성 전 실패하는 테스트를 먼저 작성하는 개발 방법론
1. RED: 구현할 기능에 대해 실패하는 테스트 코드를 작성
2. GREEN: 테스트를 통과하기 위한 최소한의 코드를 작성
3. REFACTOR: 테스트 통과를 유지하며 코드를 개선

```java
// TDD 흐름 예시
// 1. RED: 테스트 코드를 먼저 작성 (아직 구현되지 않은 메서드 호출로 에러 발생)
// 2. GREEN: 테스트를 통과하도록 메서드 최소 구현 작성
class Greeter {
  public String sayHello(String name) {
    return "Hello, " + name; // GREEN 단계를 위해 작성됨
  }
}
```

## 19.4 TDD를 도입하는 이유와 아키텍처
- 테스트하기 쉬운 코드를 작성하려 노력하면, 자연스럽게 클래스 간 결합도가 낮아지고 응집도가 높은 유연한 아키텍처가 도출됨
- TDD는 단순한 테스트 기술이 아니라 좋은 객체지향 설계를 유도하는 설계 기법

```java
// 테스트가 용이하도록 의존성 주입(Dependency Injection)을 설계하여 
// 결합도를 낮추고 유연한 아키텍처를 구현하는 예시
interface MessageService {
  String getMessage();
}

class RealMessageService implements MessageService {
  public String getMessage() {
    return "실제 서버 메시지";
  }
}

class UserController {
  private final MessageService messageService;

  // 의존성을 생성자 주입으로 외부에서 수령하도록 하여 테스트를 용이하게 함
  public UserController(MessageService messageService) {
    this.messageService = messageService;
  }

  public void showMessage() {
    System.out.println(messageService.getMessage());
  }
}
```

### 미주
[^1]: 인스턴스 (Instance): 클래스라는 설계도를 바탕으로 new 연산자를 사용하여 힙 메모리에 실제로 만들어진 구체적인 객체
[^2]: 다형성 (Polymorphism): 하나의 참조 변수나 객체가 상황에 따라 여러 가지 다양한 클래스 타입이나 동작으로 취급될 수 있는 성질
[^3]: 상속 (Inheritance): 부모 클래스가 가진 멤버(필드, 메서드)를 자식 클래스가 그대로 물려받아 코드를 확장하고 재사용하는 설계 기법
[^4]: 객체지향 (Object-Oriented): 프로그램을 단순히 명령의 나열이 아닌, 데이터와 기능을 가진 객체들의 협력으로 구성하는 개발 패러다임
[^5]: 접근 제어자 (Access Modifier): 클래스, 필드, 메서드 등의 사용 범위를 제한(public, private 등)하여 외부의 직접적인 접근을 차단하는 키워드
[^6]: 오버라이딩 (Overriding): 부모 클래스로부터 상속받은 메서드를 자식 클래스가 자신의 목적에 맞게 메서드 시그니처를 유지한 채 재정의하여 사용하는 기술
[^7]: 오버로딩 (Overloading): 한 클래스 내에 매개변수의 타입이나 개수가 다른 동일한 이름의 메서드나 생성자를 여러 개 정의하는 것
[^8]: 자료구조 (Data Structure): 컴퓨터 메모리 상에서 데이터를 효율적으로 관리하고 조직화하여 다루기 위한 저장 형식 및 프레임워크
[^9]: 인터페이스 (Interface): 클래스가 구현해야 하는 공통 메서드들의 목록과 규격을 선언해 둔 표준 계약서이자 사양서
[^10]: 추상 클래스 (Abstract Class): 온전하지 않은 추상 메서드를 포함할 수 있어, 직접 객체를 생성할 수 없고 자식 클래스가 반드시 상속받아 구현하도록 설계된 미완성 설계도
